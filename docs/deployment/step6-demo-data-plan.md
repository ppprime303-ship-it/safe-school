# STEP 6 심사위원 시연 데이터 계획(확정: 가상 학교 2곳 × 역할별 계정 4개 = 8개)

도구: `scripts/judge-demo-setup.ts`(`npm run judge:setup`), 계획: `server/src/deploy/judgeDemo.ts`, 모의 경보: `deploy/judge/mock-alerts.json`
**아직 어느 DB에도 실행하지 않았습니다.** 국내 VPS 심사 환경(`safeschool_prod_judge`)에서 마이그레이션을 마친 뒤, 승인을 받아 실행합니다.

## 1. 학교와 계정
| 학교 | 계정(이메일 `judge-<키>@judge.safeschool.invalid`) | 기존 구조 | 할 수 있는 일 / 할 수 없는 일 |
| --- | --- | --- | --- |
| **A SAFE 시연초등학교(가상)**<br>1~6학년 × 2반(21~27명), 관할 표시 인천광역시교육청, 가상 주소 인천 남동구 | a1 앱 운영담당 + 1학년 1반 담임(겸임) | `homeroom` + 업무 `app_operator` + 1-1 담임 배정 | 교직원 승인·업무 지정·학급 관리, 1학년 1반 보고 / **재난 발령 불가** |
| | a2 안전업무 담당 | `staff` + `safety_officer` | 발령·종료·상황판·훈련일지 작성 / 교직원 승인 불가 |
| | a3 교장 | `staff` + 직책 `principal` | 발령·종료·상황판·훈련일지 열람 / 교직원 승인·훈련일지 수정 불가 |
| | a4 교감 | `staff` + 직책 `vice_principal` | 교장과 같음 |
| **B SAFE 시연중학교(가상)**<br>1~3학년 × 4반(28~31명), 관할 표시 경기도교육청, 가상 주소 경기 수원시 | b1 앱 운영담당 | `staff` + `app_operator` | 교직원 승인·업무 지정 / 발령 불가 |
| | b2 안전업무 담당 + 1학년 1반 담임(겸임) | `homeroom` + `safety_officer` + 1-1 담임 배정 | 발령·종료·상황판·훈련일지 작성, 1학년 1반 보고 / **교직원 승인 불가** |
| | b3 교장 | `staff` + `principal` | 발령·종료·상황판·훈련일지 열람 |
| | b4 교감 | `staff` + `vice_principal` | 같음 |

- 직책·업무는 운영자 기록(`platform_operator`)이고, 확인 방법에는 '가상 시연학교 — 실제 학교·교직원 아님'을 적습니다. 새 권한은 만들지 않았습니다.
- 다른 학교 데이터에 접근하면 기존 규칙대로 소속이 아니므로 404입니다(A 계정으로 B 학교 주소에 접근 → 차단).
- **가상 담임 22명**: 심사 계정이 맡지 않은 학급(학교당 11개)에 '로그인 불가' 가상 담임을 배정합니다. 비밀번호가 없고 사용 중지 상태이며, 예시 훈련의 학급 보고에만 씁니다.

## 2. 학교별 시연 데이터
| 항목 | A 초등학교 | B 중학교 |
| --- | --- | --- |
| 학급 | 12개(1~6학년 × 2) | 12개(1~3학년 × 4) |
| 예시 모의훈련(`--sample-drill`) | 화재, 본관 1층 급식실 인근(가상), 운동장 대피 | 지진, 학교 전체(가상), 운동장 중앙 대피 |
| 보고 | 11개 학급 보고, **6학년 2반 미보고**, 3학년 1반 부상 1명, 일부 학급 결석 1명 | 10개 학급 보고, **2-4·3-3 미보고**, 학급별 결석 0~2명 |
| 이후 | 종료 → 훈련일지 초안(안전업무 담당 a2 / b2) | 같음 |
| 모의 경보(경보함) | 인천 남동구 호우경보 → 해제, 전국 지진 위급문자 | 경기 폭염 안내, 전국 지진 위급문자 |

모의 경보는 심사 환경에서만 허용됩니다. 제목·본문에 '[모의]'와 '실제 경보가 아닙니다'를 넣었고, DB에도 `is_mock=true`로 저장됩니다.

## 3. 실행(각 단계는 승인 후)
```bash
# 심사 환경 계정(ss-judge)으로, 심사 env 파일을 불러온 상태에서
npm run judge:setup                                                       # ① 계획만(읽기)
JUDGE_SETUP_CONFIRM=safeschool_prod_judge npm run judge:setup -- --apply --out /root/judge-accounts.txt --sample-drill   # ② 구성
JUDGE_SETUP_CONFIRM=safeschool_prod_judge npm run judge:setup -- --reset-active                                          # 심사 사이 초기화
```
- **초기화**(`--reset-active`): 두 시연 학교에서 진행 중인 상황만 종료합니다(안전업무 담당 명의). 보고, 훈련일지, 감사 기록은 삭제하지 않습니다. DB 원칙(감사 로그·원문 삭제 금지)에 따라 '삭제형 초기화'는 만들지 않았습니다. 완전히 새로 시작하려면 심사 스키마를 새 이름으로 만드는 방법을 사용자 승인 후 진행합니다.

## 4. 실제 학교 환경 차단(두 겹)
| 겹 | 방법 | 확인 |
| --- | --- | --- |
| 코드 | `DEPLOY_PROFILE=production` + `DEPLOY_DB_SCHEMA=safeschool_prod_judge`(정확히 일치)일 때만 실행. 시범운영(`safeschool_prod_pilot`)·기타 운영·Replit 시연 거부. 쓰기 작업은 확인 문구(스키마 이름)가 있어야 함 | 단위 테스트, 가짜 DB 실행 |
| DB 권한 | 실행 계정이 심사 외 SAFE SCHOOL 스키마에 USAGE 권한이 있으면 거부(관리자·시범운영 계정으로 실행하면 막힘). 심사 스키마에 시연 학교가 아닌 학교가 있으면 거부. 심사 계정 `ss_judge`는 시범운영 스키마에 권한이 없음(`deploy/sql/roles.sql`) | 로컬 PostgreSQL 16에서 실제 확인(`step6-environment-isolation.md`) |
- 데모 시드(`db:seed`)도 시범운영 스키마에서는 실행을 거부하도록 막았습니다(`ALLOW_DEMO_SEED`로도 허용되지 않음).

## 5. 비밀번호
- 계정 8개 모두 무작위 20자(대소문자·숫자·기호)입니다. 화면·로그·저장소에 남기지 않고 `--out` 파일(저장소 밖, 새 파일, 권한 600)에만 저장합니다.
- 계정을 만들기 전에 파일을 먼저 엽니다(파일 오류로 비밀번호를 잃지 않게). 이미 있는 계정의 비밀번호는 바꾸지 않습니다.
- 전달한 뒤 `shred -u`로 삭제합니다. 인증 우회 화면·API는 만들지 않았습니다(운영자 셸에서만 구성).
