# STEP 7 실제 학교 현장 시범운영 계획(준비 단계)

작성 2026-10-26 · **설계·코드·테스트·문서만. 실제 운영 DB 변경, 실제 이메일 발송, 외부 서비스 계약, API 키 발급, 배포는 사용자 승인 전에 하지 않았습니다.**
실제 학교 교직원은 가상 시연학교를 쓰지 않습니다. 시범운영 환경(`safeschool_prod_pilot`, `docs/deployment/step6-environment-isolation.md`)에서 실제 학교를 검색해 가입합니다.
SAFE SCHOOL은 학교의 공식 재난 대응·경보 시스템과 행정시스템을 **대체하지 않습니다.** 화면과 안내문에서 이 점을 계속 밝힙니다.

## 1. 실제 학교 검색·가입(기존 구현 점검)
| # | 검증 항목 | 현재 구현 | 상태 |
| --- | --- | --- | --- |
| 1 | 실제 학교 검색 API | 학교알리미 공식 OpenAPI(`schoolinfo.go.kr/openApi.do`, 학교기본정보 apiType 0). 학교명 검색 인자가 없어 학교급·시도 단위로 받아 DB 목록에 저장한 뒤 이름으로 검색. API 장애 시 마지막 목록으로 검색 | 코드 있음 / **실제 호출 미검증**(STEP 2부터 '인증키 필요'로 남아 있음) |
| 2 | 학교명·코드·주소·교육청 매핑 | `SCHUL_NM`·`SCHUL_CODE`·주소·`ATPT_OFCDC_ORG_NM` → 학교 목록. 필수 필드가 없으면 저장하지 않고 형식 오류로 멈춤 | 가상 응답 테스트 / 실제 응답 미검증. 시도 코드표는 '확인 필요' 상태. **광주·전남 통합(2026.7.1.) 뒤 시도 코드·교육청명이 바뀌었는지 확인 필요** |
| 3 | 검색 결과에서 실제 학교 선택 | 학교 선택 화면(STEP 2) | 있음 |
| 4 | 중복 등록 방지 | 같은 학교알리미 코드는 한 학교에만 연결(UNIQUE), 이미 등록된 학교는 '가입 신청'으로 안내 | 테스트 있음 |
| 5 | 최초 가입자 관리자 자동 부여 금지 | 학교 등록 신청자는 소속 '대기' + 학교 '확인 대기'로 만들어지고, **운영자가 자격 확인(공문·대표전화 등)을 기록해 승인해야** 활성화(`npm run operator -- approve`) | 테스트 있음 |
| 6 | 별도 승인 절차 | 다른 교직원은 학교 앱 운영담당이 승인 | 테스트 있음 |
| 7 | 업무용 이메일 인증코드 실제 발송 | Resend HTTP API(`MAIL_PROVIDER=resend`). 실패하면 502, 미설정이면 503. 보낸 것처럼 응답하지 않음 | 코드 있음 / **실제 발송 미검증** |
| 8 | 만료·재전송·오류 | 6자리, 10분 유효, 5회 틀리면 무효, 재발송 60초 간격·1시간 5회 | 테스트 있음 |
| 9 | 이메일 소유 확인 ≠ 교직원 자격 승인 | 이메일 인증은 계정 단계, 소속 승인은 학교별 승인 단계(분리) | 있음 |
| 10 | 다른 학교 정보 차단 | 소속이 아니면 404, 승인 대기면 403 | 테스트 있음 |
- 운영에서 개발용 console 발송은 거부됩니다. 인증코드가 화면에 표시되지도 않습니다(STEP 7 테스트 추가: `tests/step7-pilot.test.ts`).
- 메일 서비스는 Resend만 구현되어 있습니다. SMTP 등 다른 서비스가 필요하면 별도 승인 후 추가합니다.

### 1-1. 실제 학교 검색 확인 절차(승인 후, 시범운영 서버)
1. 학교알리미 OpenAPI 인증키를 발급받아 `pilot.env`에 넣습니다(사용자).
2. `npm run schoolinfo:verify`로 응답 필드를 확인하고, 결과(필드 이름, 건수)를 기록합니다. 개인정보는 없습니다.
3. `npm run directory:sync -- --kind 02 --sido <근무 학교 시도코드>`로 목록을 저장합니다.
4. 화면에서 근무 학교를 검색해 학교명·주소·교육청이 공식 정보와 같은지 확인합니다.
- 학교 이름이나 교직원 이메일은 코드·문서에 적지 않습니다.

### 1-2. 업무용 이메일 실제 수신 시험 계획
학교·교육청 메일은 외부 발신 메일을 스팸 처리하거나 차단할 수 있습니다.
| 단계 | 할 일 | 확인 |
| --- | --- | --- |
| 준비 | 발신 도메인을 정하고 메일 서비스에 SPF·DKIM 등록(DMARC 권장) | 서비스 대시보드에서 도메인 '인증됨' |
| 시험 1 | 사용자 본인의 업무용 주소 1개로 가입 → 인증코드 수신 | 받은편지함·스팸함 확인, 수신까지 걸린 시간 기록 |
| 시험 2 | 기관 메일 수신 정책 확인(학교 정보 담당·교육청 메일 관리자) | 차단되면 발신 주소를 허용 목록에 넣도록 요청 |
| 시험 3 | 재발송·만료·5회 오류 | 화면 안내가 맞는지 |
| 기록 | 성공·실패, 스팸함 여부, 지연(주소는 적지 않음) | `docs/devlog` |
- 실패하면 대체 방법(학교 대표 메일, 다른 메일 서비스)을 사용자와 정합니다. 이메일 인증을 우회하지 않습니다.

## 2. 공식 재난문자 → `official-alerts-api.md`
요약: 행정안전부 긴급재난문자 API(재난안전데이터 공유플랫폼)는 회원 가입과 활용 신청이 필요하고, 공개 페이지에는 요청 주소·응답 필드 명세가 없습니다. 어댑터는 공개된 제3자 자료를 바탕으로 **가정한 계약**으로 만들었고, 계약 테스트만 통과한 상태입니다. **실제 연동 완료가 아닙니다.**

## 3. 앱 알림 → `notifications-design.md`
요약:
- 지금은 '경보함 + 안 읽은 경보 표시'까지 있습니다.
- 앱이 열려 있을 때의 알림(동의 기반)은 서버 변경 없이 만들 수 있습니다.
- 앱을 닫아도 오는 웹 푸시는 구독 저장 테이블(DB 변경), VAPID 키, HTTPS 도메인이 필요하고, iPhone은 홈 화면에 추가한 PWA에서만 받을 수 있습니다. 승인한 뒤 진행합니다.

## 4. 개인정보·현장 운영
| 원칙 | 방법 |
| --- | --- |
| 사전 협의 | 학교 관리자(교장·교감)와 시범운영 목적·기간·참여 범위·중단 방법을 협의하고 기록 |
| 고지 | 참여 교직원에게 수집 항목(업무용 이메일, 이름, 소속·역할), 목적(로그인·소속 확인), 보관 기간, 삭제 요청 방법을 안내 |
| 최소 수집 | 이메일·표시 이름·비밀번호 해시·소속·역할만. 학생 이름·전화번호·민감정보는 받지 않음(보고는 인원 수만, 메모 200자 안내) |
| 접근 제한 | 시범운영 DB 계정(`ss_pilot`)·env 파일(640)·서버 SSH는 운영자 1~2명만 |
| 데이터 격리 | 심사 데이터와 다른 스키마·DB 계정. 심사 도구·데모 시드는 시범운영에서 실행 거부(코드 + DB 권한) |
| 공개 노출 금지 | 공개 페이지·포트폴리오·캡처에 실제 교직원 이름·이메일을 넣지 않음(캡처는 가리거나 심사 환경 화면 사용) |
| 접속 기록 | 감사 로그(로그인·승인·발령), Caddy 접속 로그(IP·경로), 보관 기간을 정해 주기적으로 정리 |
| 보관·삭제 | 시범운영 종료 후 정한 기간(예: 30일) 안에 계정·소속 데이터 삭제 또는 익명화. 절차는 승인 후 별도 도구로(이번에는 만들지 않음) |
| 공식 시스템 아님 안내 | 첫 화면·경보함에 "공식 재난 경보·대응 시스템을 대체하지 않습니다" 표시(기존 문구를 확인하고 필요하면 보완) |
- 학교가 검색된다고 해서 누구나 그 학교 공간을 만들고 관리자가 될 수는 없습니다. 운영자 자격 확인이 필요합니다(1절 5번).
