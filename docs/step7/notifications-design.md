# 앱 자체 알림 설계(분석) — 구현 전 승인 필요

작성 2026-10-26 · **이번에는 알림 기능 코드를 만들지 않았습니다.** 범위와 필요 조건을 정리했습니다.
SAFE SCHOOL 알림은 공식 재난문자(휴대폰 긴급재난문자 방송)와 같은 즉시성·도달을 **보장하지 않습니다.** 보조 안내입니다.

## 1. 현재 있는 것
- 경보 수집 → 학교 소재지 매칭 → 학교 경보함, 안 읽은 경보 수(`unreadCount`), 읽음 표시, 재송출 묶음, 해제 표시(모의 경보 기준). 모의 경보는 '모의'로 표시됩니다.
- 경보함 화면을 열어 두면 30초마다 새 경보를 다시 조회합니다. 대상 경보가 없으면 '새 재난문자 없음'을 표시합니다(STEP 7에서 문구 수정).
- 다른 화면에 있거나 앱을 닫으면 알 수 없습니다. 앱이 새 경보를 사용자에게 먼저 알리는 기능은 없습니다.

## 2. 단계별 범위
| 단계 | 내용 | 필요 조건 | 서버·DB 변경 | 비고 |
| --- | --- | --- | --- | --- |
| A. 앱 안 새 경보 표시 | 앱이 열려 있는 동안 1~2분마다 경보함을 조회하고, 새 '대상' 경보가 있으면 화면 상단에 배너와 개수 표시 | 없음 | 없음(기존 API) | iPhone·Android·PC 모두 가능 |
| B. 브라우저 알림(앱 열려 있을 때) | 사용자가 **'알림 받기'를 직접 누른 뒤**에만 권한 요청 → 새 경보가 오면 브라우저 알림 | HTTPS | 없음 | 탭이 백그라운드여도 브라우저가 열려 있으면 동작. 닫혀 있으면 안 옴 |
| C. 웹 푸시(앱을 닫아도) | 서비스 워커 + Push API. 서버가 새 대상 경보를 구독자에게 발송 | HTTPS 도메인, VAPID 키(서버 비밀값), 웹 푸시 라이브러리 | **구독 저장 테이블(마이그레이션)**, 발송 작업, 실패 기록 | Android Chrome 동작. iPhone은 **iOS 16.4 이상 + 홈 화면에 추가한 PWA**에서만 |
| D. 문자·카카오 알림 | 외부 유료 서비스 | 계약·발신번호·비용 | 큼 | 이번 범위 밖 |

권장: **A → B를 먼저 구현**(서버 변경 없음, 승인만 필요)합니다. C는 시범운영 의견을 들은 뒤 결정합니다.

## 3. 공통 규칙(구현 시)
- 대상 판정: 서버의 학교별 매칭 결과(`result=target`, 재송출 묶음 제외)만 씁니다. 화면이 지역을 다시 판단하지 않습니다.
- 동의: 기기·사용자별 명시적 동의로만 켭니다. '알림 끄기'를 언제든 할 수 있고, 동의 기록은 기기에 저장합니다(C는 서버 구독 = 동의).
- 중복 방지: 기기에 마지막으로 알린 경보 ID를 기억합니다(C는 서버가 사용자·경보별로 한 번만 발송, 실패 기록).
- 실제/모의/테스트 구분: 알림 제목 앞에 `[모의]`·`[알림 시험]`을 붙이고 색을 구분합니다. 실제 공식 경보에는 발신 기관과 '공식 재난문자 원문' 표시를 붙입니다.
- 해제·정정: 해제 경보가 오면 원래 경보에 '해제됨'을 표시하고, 알림 제목에도 '해제'를 넣습니다.
- 권한 거부·미지원: "알림이 꺼져 있습니다 — 경보함을 직접 확인하세요" 안내를 표시하고, 브라우저 설정 방법을 링크합니다.
- 알림 내용은 공식 문자 원문 요약과 '경보함에서 확인' 링크로 제한합니다. 개인정보를 넣지 않습니다.
- 시험 알림: 운영자가 '시험 알림'(실제 경보 아님, 제목 [알림 시험])을 본인 기기로만 보내 동작을 확인합니다. 실제 경보 발송이나 실제 재난을 기다리는 방식으로 시험하지 않습니다.
