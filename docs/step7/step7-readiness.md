# 실제 학교 기능 검증 준비 — 현재 구현 수준과 연동 준비 목록

작성 2026-10-26 · 표기: **구현** 코드 있음 · **자동 확인** 자동화 테스트(가짜 응답 포함) 통과 · **실제 확인** 실제 서비스·기기로 확인
**실제 API 호출·실제 메일 발송·실제 기기 확인은 아직 하나도 하지 않았습니다.** 아래 항목은 모두 '실제 확인 전'입니다.

## 1. 기능별 현재 수준
| # | 기능 | 구현 | 자동 확인 | 실제 확인 | 남은 일 |
| --- | --- | --- | --- | --- | --- |

| 2 | 업무용 이메일 인증번호 실발송 | 있음: Resend HTTP API, 6자리·10분·5회·재발송 60초·1시간 5회. 미설정이면 503, 실패면 502(보낸 것처럼 응답하지 않음) | 발송 설정·운영 모드 동작(step7-pilot) | **안 함** | 메일 서비스 계정·발신 도메인 인증 → 본인 업무 메일 1개로 수신 시험(스팸함·지연·차단 여부) |
| 3 | 학교 등록·교직원 가입 승인 | 있음: 첫 신청자에게 관리자 자동 부여 안 함 → 운영자가 자격 확인 방법을 기록해 승인(`npm run operator -- approve`), 이후 교직원은 학교 앱 운영담당이 승인, 승인 전 403·다른 학교 404 | Replit 전체 테스트·e2e(가상 학교) | **안 함** | 운영자 자격 확인 방법(공문·대표전화 등) 학교와 합의 → 실제 학교 1곳 등록·승인 |
| 4 | 공식 재난문자 API 실제 응답 형식 | 어댑터 있음, 요청 주소·필드는 **공개된 제3자 자료로 가정**(`MOIS_CBS_CONTRACT.verified=false`) | 가짜 HTTP 계약 테스트(step7-pilot) | **안 함**(활용 승인 전) | 활용 신청 → 명세 확인 → 1회 수동 조회 → 계약·테스트 수정 → `verified=true` |
| 5 | 학교 소재지 기반 경보 필터링 | 있음: 학교 주소 → 시도·시군구 → 경보 수신지역과 매칭, '전국'은 전체, 해석 불가는 '미판정'(관리자만), 재송출 묶음 | 지역 해석 12건(alerts-region), 경보 수집·매칭 DB 테스트(Replit), 가상 주소 매칭(step6-deploy) | **안 함**(실제 학교 주소·실제 문자 없음) | 실제 학교 주소가 올바른 지역으로 해석되는지, 과거 실제 문자(조회 범위)로 대상·비대상 판정 확인 |

## 2. 연동 준비 목록(신청 절차·준비물)
### 2-1. 학교알리미 OpenAPI(학교 검색)
| 단계 | 내용 | 준비물 |
| --- | --- | --- |
| 신청 | 학교알리미 누리집의 OpenAPI 메뉴에서 인증키 신청(세부 절차는 누리집 안내를 따름) | 신청자 정보, 활용 목적(학교 안전업무 보조 시범운영, 비상업), 서비스 주소 |
| 설정 | `/etc/safe-school/pilot.env`의 `SCHOOLINFO_API_KEY` | 발급 키(화면·채팅에 붙여 넣지 않음) |
| 확인 | `npm run schoolinfo:verify -- --kind 02 --sido <시도코드>` → 필드·행 수 기록 → `npm run directory:sync -- --kind 02 --sido <시도코드>` | — |
| 완료 기준 | 화면에서 근무 학교 검색 → 학교명·주소·교육청이 공식 정보와 같음 | — |

### 2-2. 업무용 이메일 인증(메일 발송 서비스)
현재 코드는 **Resend**만 지원합니다. 무료 요금제 기준 월 3,000통·하루 100통·도메인 3개, 유료(Pro)는 월 20달러부터입니다([Resend 요금](https://resend.com/pricing)). 시범운영 규모(교직원 수십 명)는 무료 범위로 예상됩니다.
| 단계 | 내용 | 준비물 |
| --- | --- | --- |
| 결정 | 메일 서비스 선택(사용자 결정). Resend는 미국 서비스이므로 업무용 이메일 주소가 국외로 전송됩니다 → 개인정보 국외 이전·처리위탁 고지 필요 여부를 학교 개인정보 담당자와 확인. 국내 서비스로 바꾸려면 발송 어댑터 추가 개발(별도 승인) | — |
| 계정 | 서비스 가입(운영자 업무 메일) | 계정 이메일, 2단계 인증 |
| 도메인 | 발신 도메인 추가(예: `mail.<보유 도메인>`) → 안내된 DNS 레코드(SPF·DKIM TXT, 필요 시 MX) 등록 → '인증됨' 확인. DMARC TXT 권장 | 도메인 DNS 관리 권한 |
| 키 | '발송 전용' 권한 API 키 발급 → `MAIL_API_KEY`, `MAIL_FROM=SAFE SCHOOL <no-reply@mail.<도메인>>` | — |
| 시험(승인 후) | 본인 업무 메일 1개로 가입 → 수신·스팸함·지연 기록. 학교·교육청 메일이 외부 메일을 막으면 정보 담당자에게 발신 주소 허용 요청 | 본인 업무 메일 |
| 완료 기준 | 실제 업무 메일로 인증번호 수신 → 가입 완료, 재발송·만료·5회 오류 안내 확인 | — |

### 2-3. 행정안전부 긴급재난문자 API(공식 재난문자) — 상세 `official-alerts-api.md`
| 단계 | 내용 | 준비물 |
| --- | --- | --- |
| 신청 | 재난안전데이터 공유플랫폼 회원 가입 → '행정안전부_긴급재난문자' 활용 신청(공공데이터포털 15134001도 같은 데이터: 개발 자동 승인, 운영 심의 승인) | 활용 목적(학교 안전업무 보조 시범운영, 비상업, 출처 표시), 서비스 개요, **VPS 공인 IP**(호출 IP 등록이 필요한 경우) |
| 확인 | 승인 후 명세서로 요청 주소·변수·응답 필드·호출 한도·해제/정정 구분 확인 | — |
| 조회 | 서버에서 1회 수동 조회 → 키·개인정보 지운 응답 샘플로 계약 테스트 자료 교체 | — |
| 수정 | `MOIS_CBS_CONTRACT` 수정·`verified=true` → Replit 테스트 → 승인 → `ALERT_PROVIDERS=mois_cbs` | — |
| 완료 기준 | 수집 기록에 실패 없음, 근무 학교 지역의 과거 실제 문자가 경보함에 '대상'으로 표시, 다른 지역은 표시 안 됨 | — |
- 실제 재난을 기다리거나 경보를 발송하는 방식으로 시험하지 않습니다. 공식 문자를 받아도 학교 내부 재난을 자동 발령하지 않습니다.
- SAFE SCHOOL 화면 표시는 휴대폰 긴급재난문자(CBS)와 같은 즉시성을 보장하지 않습니다(수집 간격 5분 + 화면 갱신 30초).

## 3. 아이폰·안드로이드 알림 확인 계획(알림 기능 승인·구현 후)
| 기기 | 확인 내용 | 기대 |
| --- | --- | --- |
| 안드로이드 Chrome | A: 앱을 연 상태에서 새 경보 배너 / B: '알림 받기' 동의 후 탭을 뒤로 보내도 알림 / C(웹 푸시 승인 시): 브라우저를 닫아도 알림 | A·B·C 모두 |
| 아이폰 Safari(일반 탭) | A / B | A만 확실, B는 제한적(지원 범위 확인) |
| 아이폰 홈 화면 추가(PWA, iOS 16.4+) | A / B / C | 모두(홈 화면에 추가한 경우만) |
| PC Chrome·Edge | A / B / C | 모두 |
- 시험 방법: 운영자가 본인 기기로만 '[알림 시험]'(실제 경보 아님)을 보내 확인. 기록: 기기·OS·브라우저 버전, 도착 여부, 지연(초), 알림 권한 거부 시 안내.
- 실패한 조합은 사용 안내서에 '지원 안 함'으로 밝힙니다. 알림이 와도 공식 재난문자를 대신한다고 안내하지 않습니다.
