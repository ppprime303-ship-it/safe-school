# 공식 긴급재난문자 API 조사·연동 설계

조사일 2026-10-26 · **실제 API는 호출하지 않았습니다(인증키 없음).** 확인한 사실과 가정한 내용을 구분해 적습니다.

| 문의 | 데이터: 재난안전데이터과, 플랫폼: Helpdesk(번호는 출처 페이지 참고) | 같은 페이지 |

## 3. 구현(`server/src/alerts/moisCbs.ts`) — 계약 테스트만 통과
- `MOIS_CBS_CONTRACT.verified = false`. 실제 응답으로 확인한 뒤에만 true로 바꾸고 이 문서에 기록합니다.
- 수집: 어제(한국 날짜)부터 최대 5페이지 × 100건, 기본 300초 간격(`MOIS_CBS_INTERVAL_SEC`, 최소 120초). 하루 최대 약 288회 × 페이지 수입니다.
- 공식 원문은 `raw`에 그대로 보존합니다(DB 트리거로 수정·삭제 불가). **발송 시각**(`CRT_DT` → `issued_at`, 한국 시간 해석)과 **수집 시각**(`received_at`)을 구분합니다.
- 지역: `RCPTN_RGN_NM`을 기존 지역 해석기로 시도·시군구로 바꾸고 학교 소재지와 매칭합니다. '전국'은 모든 학교가 대상입니다. 해석할 수 없으면 '미판정'으로 남기고 관리자에게만 보입니다(기존 규칙).
- 중복·재송출: 같은 `SN`은 한 번만 저장합니다. 같은 문구·지역이 짧은 시간 안에 다른 SN으로 오면 '재송출'로 묶어 다시 알리지 않습니다(기존 collector).
- 해제·정정: 명세에 구분 필드가 확인되지 않아 **추정하지 않고** 새 문자로 저장합니다. 본문의 '해제' 여부는 사람이 판단합니다. 필드가 확인되면 msgType 대응을 추가합니다.
- 실패: 429(호출 제한)·HTTP 오류·결과 코드 오류·형식 불일치는 수집 실패로 기록하고(재시도 2회, 인증키는 로그에서 가림) 다음 주기에 다시 시도합니다. 형식이 맞지 않는 항목은 버리고 건수만 기록합니다.
- 새 문자가 없으면 경보함에 '새 재난문자 없음'으로 표시합니다(빈 body는 오류가 아님).
- **공식 재난문자를 받아도 학교 내부 재난을 자동으로 발령하지 않습니다.** 학부모 발송도 하지 않습니다.
- 환경: 시범운영(pilot)만. 심사 환경에서 `mois_cbs`를 켜면 서버가 시작하지 않습니다.

## 4. 테스트(`tests/step7-pilot.test.ts`, 가짜 HTTP — 실제 호출 없음)
- 시각 해석 3가지 형식과 잘못된 날짜 거부, 필드 대응·원문 보존·발신 기관 표시, 단계 대응, 전국 지역, 필수 값 누락 버림, 재송출 내용 해시
- 요청 주소(키 인코딩), 빈 응답('새 재난문자 없음'), 여러 페이지, 429·500·결과 코드·형식 오류, 오류 기록에 인증키 없음
- 테스트 통과는 **'가정한 계약대로 동작한다'는 뜻일 뿐**입니다. 실제 연동 완료가 아닙니다.

## 5. 신청·확인 절차(사용자 승인 후)
1. 재난안전데이터 공유플랫폼에 회원 가입하고 '행정안전부_긴급재난문자' 활용을 신청합니다. 활용 목적에는 학교 안전업무 보조 시범운영, 비상업, 출처 표시를 적습니다. 공공누리 조건 때문에 상업적 이용·변경을 하지 않는 범위인지 확인합니다.
2. 승인되면 명세서에서 요청 주소·변수·응답 필드·호출 한도·호출 IP 등록 여부를 확인합니다. 필요하면 VPS 공인 IP를 등록합니다.
3. 시범운영 서버 셸에서 **1회 수동 조회**로 응답 구조를 확인합니다. 인증키는 화면에 출력하지 말고, 응답 샘플에서 개인정보·키를 지운 뒤 계약 테스트 자료로 저장합니다.
4. 계약(`MOIS_CBS_CONTRACT`)과 테스트를 실제 형식에 맞게 고칩니다 → Replit 테스트 → 승인 → `ALERT_PROVIDERS=mois_cbs`
5. 실제 재난 발생을 기다리거나 경보를 발송해서 시험하지 않습니다. 이미 발송된 과거 문자(조회 범위)로 수집·매칭을 확인합니다.
