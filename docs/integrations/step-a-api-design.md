## 1. P0-1 경보함 수집 상태 표시
**문제:** 공식 수집이 꺼져 있거나 실패해도 경보함은 "새 재난문자 없음 — 우리 학교 지역에 해당하는 경보가 없습니다"로 보였습니다(안심 표현).

**설계**
- 근거: 수집 기록 `alert_collection_runs`(기존) + 서버 시작 때 실제로 켠 공급자(`setConfiguredAlertSources`, `index.ts`). DB 변경 없음.
- `server/src/alerts/feedStatus.ts` `getAlertFeedStatus()` → `GET /api/schools/:id/alerts` 응답에 `feed` 추가(기존 필드 그대로).
- 공식(mois_cbs) 상태: `not_configured`(수집 꺼짐) → `never_succeeded`(한 번도 성공 못 함, 실패 기록이 있어도) → `failing`(마지막 시도 실패) → `stale`(마지막 성공이 수집 간격 3배·최소 15분보다 오래됨) → `ok`. **성공 기록이 없으면 절대 ok 아님.**
- 오류는 원문 대신 종류만 화면에(호출 한도·인증 거부·제공기관 서버 오류·시간 초과·형식 변경·연결 실패·알 수 없음). 원문은 서버 기록에만(인증키는 이미 가림).
- 모의 공급자 성공은 공식 상태에 영향 없음. 모의가 켜져 있으면 "모의(가상) 경보 — 공식 경보 아님" 띠.
- 학교와 무관한 서버 전체 상태 → 학교 간 정보가 섞이지 않음(다른 학교 경보함 404 그대로).

**화면(`AlertsPage.tsx`)**
| 상태 | 표시 |
| --- | --- |
| not_configured | 주황: "공식 재난문자 수집이 연결되어 있지 않습니다 … 휴대전화 긴급재난문자·방송 등 공식 경로로 확인하세요" |
| never_succeeded | 빨강: "공식 재난문자를 아직 한 번도 받아오지 못했습니다" + 마지막 실패 시각·종류 |
| failing | 빨강: "받아오지 못하고 있습니다" + 마지막 성공·실패 시각·종류, "그 뒤의 경보는 없을 수 있음" |
| stale | 주황: "확인이 늦어지고 있습니다" + 마지막 확인 시각 |
| ok | 회색 한 줄: "공식 재난문자 마지막 확인 ○시 ○분(○분 전)" — '실시간'이라 하지 않음. 응답 형식 확인 전이면 "응답 형식 확인 전 시범 수집" |
- 경보가 없을 때: ok 이면 기존 "새 재난문자 없음", 그 밖이면 "표시할 경보 없음 — 수집 상태 안내를 확인하세요. 경보가 없다는 뜻이 아닐 수 있습니다".
- 모의 경보 표시 강화: 배지 "모의(가상)", 펼친 내용 제목 "모의 경보 내용(시연용 가상 — 공식 경보 아님)"(이전에는 모의도 "공식 경보 원문"이라고 표시).
- **화면 육안 확인은 하지 않았습니다**(빌드 성공·API 테스트로만 확인). 평가 전 점검표에 항목 추가.

**동작**
- 검색(`GET /api/school-directory?q&kind&sido&sgg`): 시군구를 주면 그 시군구 목록으로 최신 여부를 판단하고 7일 넘으면 그 시군구만 다시 받음. 시군구가 없으면 기존 방식(시도·전국) 그대로.
- `SCHOOLINFO_SGG_REQUIRED=true`: 시군구 없는 요청은 API를 부르지 않고 저장된 목록 + "시군구를 선택하세요" 안내. 학년별 자료도 학교의 시군구를 모르면 부르지 않고 저장 자료.
- 장애·키 없음: 기존대로 저장된 목록·스냅숏(stale 표시). 키 없으면 클라이언트 null(호출 안 함).
- DB: `school_directory_entries.sgg_code`(NULL 허용) + 색인 — 마이그레이션 `20261027000000_directory_sgg_code`(추가만, DROP 없음). 로컬 테스트 스키마에 적용, 스키마 정의와 차이 없음 확인.
- 운영자 도구: `npm run directory:sync -- --kind 02 --sgg 41111`, 시군구 필수 모드에서 `--sido 41`은 그 시도의 시군구를 차례로(1초 간격). `npm run schoolinfo:verify -- --sgg <코드>` 추가.

**남은 위험:** 경보 지역 판정(`alerts/region.ts`)에 '전남광주통합특별시'가 없음 → 그 지역 학교의 경보가 '미판정'이 될 수 있음. 재난문자의 통합시 지역명 표기를 확인한 뒤 수정 필요(이번 범위 밖).

| 확인 못 함 | JSON 감싸는 구조(head·row) 실제 예시, 일별 한도 수치, 시도교육청 코드표(전남광주 통합 후) |

**구현(`server/src/integrations/neis.ts`, 서버 전용)**
- `NEIS_API_KEY`(서버 환경변수, `env.ts` 검증). 없으면 `getNeisClient()` = null → 호출하지 않음(샘플 5건 오인 방지).
- 응답 검증: zod로 행별 필수 필드(교육청 코드·학교 코드·학교명), 맞지 않는 행은 버리고 건수, 전부 맞지 않거나 감싸는 구조가 다르면 `format`.
- 시간 제한 10초, 연결 실패·시간 초과·5xx 1회 재시도(인증·요청 오류·한도 초과는 재시도 안 함), 호출 직렬화·최소 간격 200ms, **서버 하루 상한**(`NEIS_DAILY_LIMIT`, 기본 900, 한국 날짜), 같은 요청 12시간 캐시(최대 200개).
- 인증키는 오류 문장에서 가림(`KEY=` 형태 + 키 문자열 그대로 되돌려 받는 경우까지 — 테스트가 찾아낸 빈틈을 고침).
- 교육청 코드 매핑: 코드표를 하드코딩하지 않고 응답의 코드·이름 쌍을 그대로 사용.
- 학교 코드 매핑: `matchNeisCandidates()` — 학교알리미 학교(이름·교육청명·도로명주소)와 나이스 후보를 비교해 high/medium 후보만. **DB에 쓰지 않음**(연결은 관리자 확인 후, 화면 없음).
- 화면·API 경로 연결 없음. 운영 DB 학교 정보 덮어쓰기 없음.
- 실제 확인 도구: `npm run neis:verify -- --name <학교명>`(승인 후 실행, 키·값 비출력).
