## 나이스 HTTP 500 분석

**갱신:** 사용자 실측(키 없는 같은 요청)에서 기본 fetch는 HTTP 200, `Accept: application/json`은 HTTP 500(HTML)이 반복되어 이 헤더가 유력 원인입니다. 어댑터에서 제거했습니다. 인증키 요청의 정상 응답은 미확인이며, 아래는 그 전의 분석 기록입니다.

10월 27일 8회 모두 WebtoB 단계의 HTML 500이었고, 틀린 키·없는 학교·한글 없는 요청에서도 같았습니다. 11월 2일 승인 호출(교육청코드 E10)도 HTTP 500입니다. 나이스 결과 코드까지 가지 못했으므로 어댑터 결함이나 키 문제의 근거가 없습니다. 요청 주소는 10월 27일 확인한 공식 명세와 일치하며, 포털 안내 페이지 본문에는 장애 공지나 호출 제한 안내가 없었습니다.

포털 첫 화면 공지사항에도 Open API 장애 공지가 표시되지 않았습니다(공지가 없다고 장애가 아니라는 뜻은 아닙니다). 앱 코드는 나이스를 호출하지 않으므로(`getNeisClient` 사용처 없음, 확인 도구만 사용) Beta 차단 요인이 아닙니다.

제공기관 장애, 비브라우저 요청 처리, 학교망 송신 IP 중 어느 것인지는 미확인입니다. 구분 방법은 브라우저에서 키 없는 샘플 주소를 여는 것입니다. 브라우저도 500이면 제공기관 쪽, JSON이 보이면 호출 환경 차이이므로 KERIS에 문의합니다. 헤더 위장으로 우회하지 않습니다. 어댑터는 이제 500의 응답 형식(HTML·JSON)을 기록합니다. 나이스는 현재 화면에서 쓰지 않으며 `NEIS_CONTRACT.verified=false`입니다.

## 긴급재난문자 명세 대조

공유플랫폼 데이터 228 '오픈 API' 탭의 공개 명세와 대조했습니다.

| 항목 | 공식 명세 | 어댑터 |
|---|---|---|
| 주소·메서드 | GET `https://www.safetydata.go.kr/V2/api/DSSP-IF-00247` | 일치 |
| 인자 | `serviceKey`(필수), `numOfRows`, `pageNo`, `returnType`, `crtDt`(YYYYMMDD), `rgnNm` | 일치(`rgnNm` 미사용) |
| 항목 | `SN`, `CRT_DT`, `MSG_CN`, `RCPTN_RGN_NM`, `EMRG_STEP_NM`, `DST_SE_NM`, `REG_YMD`, `MDFCN_YMD`, `RCPTN_RGN_ID`, `EMRG_STEP_ID`, `DST_SE_ID` | 사용 항목 일치, 나머지는 원문 보존 |
| 정정·재송출·취소 | 구분 항목 없음(수정일자만) | 내용 해시로 재송출 묶음, 정정·취소는 본문으로 사람이 판단 |

**코드 32:** 공식 오류표에 `UNREGISTERED IP ERROR`(등록되지 않은 IP)로 정의되어 있습니다. 사용자 확인으로 등록 IP는 기존 SAFE SCHOOL 서버의 공인 IP이므로, 학교 PC에서 호출한 결과로 설명됩니다. 메시지 문구는 출력하지 못했습니다. 학교 PC에서 재호출하면 같은 결과가 나올 것이므로 추가 승인 1회는 쓰지 않았고, 로컬 IP를 등록하지도 않습니다. 정상 응답 검증은 등록된 서버에서 일회성 도구로 합니다(`docs/beta2/release/beta-deploy-plan.md` 2절, 서버 접속은 별도 승인).

**호출량:** 키 전체 하루 100건입니다. 기본 30분 간격(하루 48회), 상한 60, 주기당 1쪽, 재시도 없음이며 15분 미만은 허용하지 않습니다. 상한은 같은 DB를 쓰는 서버끼리만 공유되므로 환경별 배분이 필요합니다(같은 문서 3절). 제공기관이 호출 제한을 알리면 그날은 더 호출하지 않습니다. 갱신 주기는 1분이지만 최대 30분 지연이 생기며, 더 빠른 수신이 필요하면 공유플랫폼(044-205-8461·8462)에 이용량 증설을 문의해야 합니다.

**확인 전:** 정상 응답의 `body` 구조와 정렬 순서입니다. 1쪽 100건에 최신 문자가 들어오는지 알 수 없습니다. `rgnNm`은 '전국' 문자 포함 여부를 몰라 쓰지 않습니다. `MOIS_CBS_CONTRACT.verified=false`를 유지하고 자동 수집을 켜지 않습니다. `MOIS_CBS_CONTRACT.verified=false`를 유지하고, Beta는 이 상태에서 수집을 켜면 시작을 거부합니다.

## 교직원 자동 안내(가짜 응답으로만 검증)

공식 API → 서버 수집(`official_alerts`) → 학교 지역 판정(`school_alert_matches`) → 교직원별 미확인(`alert_reads`) → 30초 조회 안내 창. 브라우저는 저장된 자료만 읽습니다.

| 규칙 | 내용 |
|---|---|
| 우선순위 | 경보·중대경보·위급·긴급은 우선, 주의보·안전안내는 일반. 예비특보는 수집하지 않음(경보함 기상청 현황 원문으로만) |
| 재안내 | 정정·변경은 다시 안내, 연장은 이미 확인했으면 안내 안 함 |
| 해제 | 안내하지 않고 경보함의 기존 경보를 '해제됨'으로 갱신 |
| 사건 진행 중 | 창을 띄우지 않고 화면을 막지 않는 안내 줄 표시(대피 보고 우선) |
| 경계 | 학교 재난 자동 발령 없음, 대피 권고 문구 없음, 경보함에서 읽으면 확인으로 처리 |

기상특보 수집·안내에는 마이그레이션 `20261103000000_kma_warning_provider`와 `ALERT_PROVIDERS=kma_warning`이 필요합니다.
