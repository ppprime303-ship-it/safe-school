## 1. 문제 원인
- 편집 화면에 저장 단추가 3종: `저장`(현재 상태 유지), `작성 완료로 저장`, `작성 중으로 바꿔 저장`. 세 단추 모두 같은 API(`PATCH /notices/:id`)를 부르고 `status` 값만 달랐음 → **'작성 상태 변경'이 '저장'과 한 단추에 묶여** 무엇을 눌러야 할지 판단하기 어려움.
- 예시문 21개 중 한 유형의 카드 3개와 유형 단추 7개가 늘 펼쳐져 있어 모바일에서 편집 영역이 아래로 밀림.
- `이 안내문 취소`가 저장 단추 바로 아래 같은 영역에 있어 일반 작업과 구분이 약함.

## 3. 저장·상태 전환 로직(`client/src/lib/noticeSave.ts`)
- `저장하기` = 제목·본문·예시 키 + **선택한 작성 상태**를 PATCH 한 번으로 저장(판 +1, 409 충돌·감사 기록·DB 이력 그대로).
- 상태를 건드리지 않으면 기존 상태를 그대로 보냄(본문만 고쳐도 '작성 완료' 유지). 상태만 바꿔도 저장 1건(판 +1).
- 바뀐 것이 없으면 요청하지 않고 단추 비활성('저장할 변경 사항이 없습니다').
- 새 안내문: DB 규칙상 '작성 중·판 1'로 만들고, '작성 완료'를 골랐으면 이어서 상태만 저장(판 2) — 기존과 같음.
- 두 번 누르기 방지: 처리 중 단추 비활성 + 요청 중복 차단(ref).
- '작성 완료'는 앱 안 문안 상태일 뿐 공식 결재(K-에듀파인)·실제 발송이 아님을 상태 선택 아래와 저장 메시지에 표시.
