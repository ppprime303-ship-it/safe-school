# SAFE SCHOOL
### AI 협업 개발을 통한 학교 안전업무 지원 플랫폼

| 항목 | 내용 |
| --- | --- |
| 출품 | 행정안전부 「2026 바이브 코딩 기반 재난안전 분야 업무시스템」 경진대회 |
| 개발 방식 | AI 기반 기획·개발·검증(사용자 + ChatGPT + Claude + Replit + GitHub) |
| 기록 기준일 | 2026년 10월 23일 |
| 상태 | STEP 1~5 개발 완료(자동화 테스트 564건 통과, 사용자 Replit 확인). STEP 6~8은 계획 단계 |

> SAFE SCHOOL은 학교의 공식 행정시스템(K-에듀파인 등)이나 법정 보고 절차를 **대체하지 않는 보조 서비스**입니다. 실제 재난 경보 발송, 학부모 자동 발송, 전자결재는 하지 않습니다.
> 이 원고의 수치는 저장소 코드·커밋과 사용자가 알려 준 Replit 실행 결과에 근거합니다. 업무시간 절감률, 성능 수치, 운영 실적은 측정하지 않았으므로 적지 않았습니다.

## 1장. 프로젝트 배경
- **정보가 흩어져 있음:** 학교 안전업무에 필요한 정보가 여러 곳에 나뉘어 있습니다. 재난 대응 연락과 보고, 기상특보·재난문자, 안전교육 자료(교육부·행정안전부 누리집), 시설 안전 법령(국가법령정보센터), 교육청 지침(17→16개 교육청 누리집)이 각각 다른 곳에 있습니다.
- **처리 과정이 불편함:** 재난·훈련 때 학급별 대피 인원을 모으고, 미보고 학급을 확인하고, 훈련일지를 작성하는 일을 수작업으로 합니다.
- **한곳에서 볼 수 있는 환경이 필요함:** 담임·안전업무 담당·관리자가 자기 역할에 맞는 화면에서 필요한 정보만 보는 환경이 필요합니다.
- **기존 시스템을 대체하지 않는 보조 서비스:** 공식 계획·실적·결재는 기존 시스템에서 하고, SAFE SCHOOL은 현장 대응과 자료 탐색을 돕습니다. 이 원칙에 따라 개발 중 일부 기능은 의도적으로 취소했습니다(6장 STEP 4).

## 2장. 문제 정의
| 문제 | 현장 상황 | SAFE SCHOOL의 접근 |
| --- | --- | --- |
| 재난 대응 시 보고·정보 확인 | 학급별 대피 인원·부상·미확인 인원을 빠르게 모아야 함 | 학급 보고 → 실시간 상황판, 미보고를 '완료'로 표시하지 않음 |
| 안전교육 자료 탐색 | 공식 자료가 여러 누리집에 흩어져 있음 | 공식 제공처 안내, 학교급·7대 영역으로 찾기 |
| 시설관리 법령·지침 탐색 | 법령·고시·교육청 지침이 따로 있고 개정 여부를 알기 어려움 | 국가 법령 우선, 관할 교육청 우선, 확인된 최근 개정 표시 |
| 권한에 따른 정보 접근 | 교장·교감·안전 담당·담임이 할 수 있는 일이 다름 | 기본 역할 + 직책·업무를 합산한 권한, 요청마다 서버에서 다시 검사 |

## 5장. 시스템 설계
**구성**
```
브라우저(React 19 + Vite 6 + Tailwind 4, 모바일 우선 반응형)
   │  /api (세션 쿠키)
   ▼
Express 5 서버(TypeScript, zod 입력 검증)
   │  Prisma 6
   ▼
PostgreSQL ── 스키마 분리: safeschool_browser_demo(시연) / safeschool_test(자동 테스트, 매번 비움)
```
버전은 `package.json` 기준입니다. express ^5.1.0, react ^19.1.0, vite ^6.3.0, typescript ^5.8.0, prisma·@prisma/client ^6.10.0, tailwindcss ^4.1.0, vitest ^4.0.0, zod ^3.25.0, Node >=20.19.

| 영역 | 설계 |
| --- | --- |
| 인증·권한 | 세션 로그인. 권한 = 기본 역할(관리자·담임·교직원) + 직책(교장·교감) + 업무(안전업무 담당·앱 운영담당) 합산(`shared/permissions.ts`). 서버가 요청마다 DB에서 다시 계산(`resolveAccess`). 발령·종료 요청 수 제한 |
| 학교별 데이터 분리 | 모든 학교 화면·API에 `schoolId`가 들어가고, 승인된 소속이 있어야 접근 가능 |
| 데이터베이스 | 모델 30개, 마이그레이션 5개(10/20~10/23). 이메일 소문자·보고 합계·감사 로그 수정 금지 같은 제약을 DB에서 강제 |
| 모의 재난 경보 | 모의 공급자가 경보를 수집 → 원문은 수정·삭제할 수 없게 저장 → 학교 소재지와 비교해 대상·미판정 결정 → 경보함 표시. 실제 경보 기관과 연결하지 않음 |
| 공식 외부 자료 | 정적 데이터 파일에 공식 주소·근거·확인일·확인 등급을 기록. https와 허용 도메인만 링크하고 새 탭(`noopener noreferrer`)으로 열기. 법령은 국가법령정보센터 '현행' 바로가기. 크롤링·외부 API 없음 |
| 배포 안전 | 배포 때 대상 스키마를 필수로 검증(public·test 스키마 거부)한 뒤 같은 주소로 마이그레이션과 서버를 시작. 오류 로그에서 이메일·전화·DB 주소를 가림 |

## 12장. 프로젝트 성찰 및 발전 가능성
- **AI 협업의 의미:** AI는 코드 구현·조사·테스트를 빠르게 해냈습니다. 반면 '무엇을 만들지 않을지'는 학교 현장의 판단으로 정했습니다(STEP 4 계획·실적 기능 취소, STEP 5 점검 기록 제외).
- **검증의 중요성:** AI가 만든 결과는 실제 실행으로만 확인했습니다. 실행하지 못한 테스트는 '실행 못 함'으로 따로 기록했고, Replit 전체 테스트와 실제 화면 검수를 거친 뒤에만 완료로 처리했습니다. 테스트 데이터 오류처럼 실제 실행에서 드러난 문제를 검증 로직을 약화시키지 않고 고쳤습니다.
- **공식 출처의 변화:** 지시서는 17개 교육청을 전제로 했지만, 확인해 보니 16개(광주·전남 통합)였습니다. 공식 자료는 시점에 따라 달라지므로 확인일과 갱신 절차를 함께 남겼습니다.
- **한계:** 교육청 지침 원문 대부분을 확인하지 못했습니다. 법령 변경 자동 감시, 운영 보안 점검, 실제 사용자 평가는 앞으로 할 일입니다.
- **발전 가능성:** 현장 의견에 따라 시설 업무 지원 범위를 정하고, 공식 API로 법령 변경을 확인하는 기능을 더할 수 있습니다. 다른 학교에도 쓸 수 있도록 관할 교육청 데이터를 보강할 수 있습니다.
