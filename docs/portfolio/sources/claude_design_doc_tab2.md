## 검토 결과: 수정이 필요한 12개 항목

현재 설계는 재난 중 보고·집계는 줄이지만, 그 전후에 교직원의 새 업무를 많이 만듭니다. 가입·승인, 재적 입력, 훈련계획 재입력, 점검표 이중 작성이 그렇습니다. 또 **결석한 학생을 ‘미확인’으로 잡는 구조**는 업무를 늘리고 상황판 정확성도 떨어뜨리므로 가장 먼저 고쳐야 합니다.

아래는 제안이며, 승인하시면 기본 설계 탭(A·C·D·E절)에 반영합니다.

| # | 현재 설계 | 업무경감 관점의 문제 | 수정 제안 | 고칠 곳 | 우선 |
| --- | --- | --- | --- | --- | --- |
| 1 | 대피확인 + 미확인 = 재적 | 결석·조퇴·외부활동 학생이 ‘미확인’으로 잡혀, 관리자가 아닌 경보를 확인하는 연락이 늘어남 | ‘사전 파악 부재(결석·조퇴·외부활동)’를 따로 받음. 미확인 = 재적 − 대피확인 − 사전부재 | A-1, C-2 CHECK, D, E | P0 |
| 2 | 담임이 숫자를 직접 입력 | 대부분의 반은 ‘전원 확인’인데도 숫자를 입력해야 함 | ‘전원 확인’ 버튼 1번으로 보고. 예외가 있을 때만 +/− 버튼 | D, E | P0 |
| 3 | 재적 변경 시 사유를 글로 입력 | 재난 중 타이핑은 부담이고 느림 | 사유는 버튼 선택(전출·전입·기타), 글은 선택. 이력은 그대로 보존 | A-1, D | P0 |
| 4 | 교직원 각자 가입 → 이메일 인증 → 관리자가 한 명씩 승인·학급 배정 | 교직원 전원에게 가입 업무가, 관리자에게는 사람 수 × 3회의 클릭이 생김 | 관리자가 기존 교직원 명단(이름·이메일·담당학급)을 붙여넣어 일괄 초대. 초대 메일의 링크로 비밀번호만 정하면 인증·승인·배정이 한 번에 끝남. 관리자의 사람 확인 원칙은 명단 작성 단계에서 충족 | A-1, D, E | P0 |
| 5 | 학급·재적을 화면에서 하나씩 입력 | 이미 가진 엑셀 자료를 다시 입력 | 엑셀에서 표를 복사해 그대로 붙여넣기. 미리보기로 확인 후 저장 | D, E | P0 |
| 6 | 재난 시 담임이 앱을 열어 찾아 들어감 | 로그인 만료·메뉴 탐색으로 보고가 늦어짐 | 발령 시 교직원에게 푸시를 보내 누르면 우리 반 보고 화면이 바로 열림. 세션 30일, 홈 화면 앱 설치 안내. 학교 방송·비상벨은 그대로 주 경보 수단 | A-1, B, E | P0 |
| 7 | 상황 보고서 서식을 임의로 설계 | 담당자가 교육청·학교안전지원시스템 서식에 다시 옮겨 적어야 할 수 있음 | 실제로 제출하는 서식(훈련 결과보고 등)을 받아 같은 항목·순서로 출력 | F, H | P0(서식 필요) |
| 8 | 학부모 안내를 채널별로 복사 | 복사·붙여넣기가 채널 수만큼 반복되며, e알리미·하이클래스와 이중 발송 위험 | 승인 1번으로 웹푸시·공개페이지는 자동. 학교가 쓰는 채널 하나만 ‘주 채널’로 지정해 복사 버튼 1개만 표시 | D, E | P0 |
| 9 | 시설 안전점검 체크리스트 전체 | 행정실의 법정 소방·시설 점검과 중복되고, 교직원에게 새 점검 업무가 생김 | 전체 점검표 대신 ‘위험요소 신고(사진 1장 + 장소)’와 조치 추적을 우선. 정기 점검표는 행정실과 협의 후 선택 기능으로 | A-1, D, H | P1 |
| 10 | 연간 훈련계획을 앱에 입력 | 학교안전계획(한글 문서)을 다시 입력하는 중복 | 계획 입력은 선택. 훈련 모드로 발령하면 실적이 자동으로 쌓이고, 평가는 종료 화면에서 한 번만 입력 | A-1, D | P1 |
| 11 | 행동요령을 앱에서 편집 | 학교 매뉴얼을 다시 타이핑 | 기본 요령(출처 표시) + 학교 기존 매뉴얼 PDF 업로드로 대체 | D | P1 |
| 12 | 사용 후기를 종이·별도 양식으로 수집 | 후기 취합이 또 하나의 업무 | 훈련 종료 후 앱이 역할별 평가(5점 척도 + 의견)를 한 번 요청하고 자동 집계 | 신규(FR-EVAL) | P1 |

일정 영향: 1\~6번은 이미 계획된 STEP 2\~3 안에서 처리되고, 12번은 STEP 4에 약 반나절을 더합니다(추정). 7번은 실제 서식이 있어야 진행할 수 있습니다.

**확인이 필요한 것**

- [ ] 대피훈련 후 제출하는 결과보고 서식(학교안전지원시스템 입력 항목 또는 교육청 양식) 1부
- [ ] 학부모 안내에 주로 쓰는 채널(e알리미, 하이클래스, 학교 문자 중)
- [ ] 학급별 인원을 관리하는 엑셀 파일의 열 구성(학년·반·인원)
- [ ] 행정실의 정기 시설점검 범위와 중복 여부

## 확정된 설계 변경(10-20, 사용자 결정)

아키텍처와 기존 요구사항은 유지하고, 아래 DB·API·테스트 항목만 바꿉니다. STEP 1 코드에는 DB 부분이 반영되었고, API는 STEP 2\~3에서 구현합니다.

| 영역 | 변경 전 | 변경 후 | 반영 위치 |
| --- | --- | --- | --- |
| 가입 승인 | 교직원 한 명씩 관리자 승인 | 관리자가 소속을 확인한 명단으로 일괄 초대. 초대받은 사람은 이메일 인증만 하면 자동 승인되고, 명단에 없는 자가가입만 개별 승인 | DB: staff\_invitations, invitation\_assignments, memberships.approval\_method / API: STEP 2 |
| 학급·업무 배정 | 사람마다 배정 | 명단 붙여넣기로 학급·업무를 함께 배정, 일괄 수정 가능 | DB: invitation\_assignments → class\_assignments |
| 부상자 | 부상자 ≤ 대피확인(부상자는 대피 완료자) | 제약 제거. 부상자 수는 대피 여부와 별도로 관리(부상자 ≤ 재적만 검사) | DB CHECK, 테스트 |

| 실증 | 가설 표 | 기존 절차 비교표, 앱 자동 시각 기록, 후기를 묶음. 실측값과 예상치를 구분하고, 설문만으로 시간 단축을 주장하지 않음 | 아래 A\~F |

| 일반 교직원(1) | T10 배정 학급 대리 보고, 위험요소 사진 신고 | 각 1분 이내 | 배정되지 않은 학급은 보이지 않는지 |
| 학부모 역할(교직원 1) | T11 QR로 공지 페이지 접속·알림 구독 | 1분 이내(Android) | iPhone 안내가 이해되는지 |

기록지 열: 역할 · 과제 · 시작→완료 초 · 성공 여부 · 도움 요청 횟수 · 관찰 메모. 화면 녹화는 참가자 동의를 받은 경우에만 합니다.

## B. 5점 척도 평가 문항

1점은 ‘전혀 그렇지 않다’, 5점은 ‘매우 그렇다’입니다. 모든 역할이 같은 10문항에 답하고, Q4와 Q8은 반대 방향 문항이라 분석할 때 점수를 뒤집습니다.

| # | 영역 | 문항 |
| --- | --- | --- |
| Q1 | 업무경감 | 이 앱을 쓰면 재난·훈련 때 내 업무가 줄어들 것 같다. |
| Q2 | 업무경감 | 같은 내용을 여러 곳에 다시 입력하지 않아도 된다. |
| Q3 | 업무경감 | 보고·집계·문서 작성에 드는 시간이 줄어들 것 같다. |
| Q4 | 새 업무(역문항) | 이 앱 때문에 새로 해야 하는 일이 부담스럽다. |
| Q5 | 사용성 | 설명 없이도 필요한 화면을 찾을 수 있었다. |
| Q6 | 사용성 | 긴급한 상황에서도 휴대폰으로 쉽게 보고할 수 있을 것 같다. |
| Q7 | 정확성·신뢰 | 상황판의 숫자와 상태(미보고·미확인·부상)를 믿을 수 있다. |
| Q8 | 정확성(역문항) | 입력하다가 실수할 것 같은 부분이 있었다. |
| Q9 | 보안·안심 | 개인정보가 적절히 보호된다고 느꼈다. |
| Q10 | 지속 사용 | 다음 훈련에서도 이 앱을 쓰고 싶다. |

답변에는 역할과 사용한 기능만 함께 받고, 이름은 후기 공개에 동의한 경우에만 받습니다. 표준 척도가 필요하면 SUS(시스템 사용성 척도) 10문항을 더해도 됩니다. 한국어 번역본은 출처 확인이 필요합니다.

## C. 자유 의견·개선 요구 수집과 재테스트

**수집 문항(서술)**

1. 가장 편했던 기능과 그 이유는?
2. 불편했거나 헷갈렸던 화면과 버튼은?
3. 기존 업무에서 없어진 일과 새로 생긴 일은?
4. 실제 재난 때 이 앱을 쓰지 못할 것 같은 이유가 있다면?
5. 꼭 바뀌었으면 하는 점 한 가지는?

**개선 요구 처리 절차**

1. 모든 의견을 ‘개선 목록’ 표에 옮깁니다. 열은 번호, 역할, 기능, 원문, 심각도, 조치, 상태, 재테스트 결과입니다.
2. 심각도는 세 단계로 나눕니다. **상**은 재난 중 보고 실패나 잘못된 숫자로 이어질 수 있는 것, **중**은 업무를 늘리거나 헷갈리게 하는 것, **하**는 표현·배치입니다.
3. 두 명 이상이 지적했거나 평가 문항 평균이 3.5점 미만인 기능은 우선순위를 한 단계 올립니다.
4. ‘상’은 제출 전에 반드시 고칩니다. ‘중’은 일정이 허락하는 만큼 고치고, 나머지는 보고서의 ‘향후 계획’에 적습니다.
5. 고친 기능은 지적한 사람이 같은 과제(A의 T번호)로 다시 테스트합니다. 결과는 ‘재테스트 결과’ 열에 통과/미통과로 남깁니다.
6. 개선 전후 화면을 캡처해 두면 제출자료의 ‘AI 협업을 통한 고도화’ 증빙으로 쓸 수 있습니다.

앞서 제안한 것처럼 이 수집을 앱 안에 넣으면 취합 업무도 없어집니다. 검토 결과 12번(훈련 종료 후 평가 요청)이 그 내용입니다.

## D. 기존 방식 대비 소요시간 측정 계획

기존 업무의 시간 기록이 없으므로, 같은 가상 상황을 두 방식으로 재현해 재는 **탁상 비교 측정**을 합니다. 결과는 ‘모의 측정치’로 표기하며, 실제 재난의 시간 단축을 입증한 것으로 쓰지 않습니다.

| 구분 | 내용 |
| --- | --- |
| 상황 카드 | “지진 훈련, 6개 학급, 결석 2명·미확인 1명·부상 1명” 같은 카드를 미리 만들어 담임 역할자에게 나눠 줌 |
| A안(기존 방식) | 담임 → 메신저·전화로 보고, 담당자 → 종이 집계, 학부모 안내문 작성, 결과보고 한글 문서 작성 |
| B안(SAFE SCHOOL) | 같은 카드로 앱 발령·보고·상황판·안내 승인·보고서 저장 |
| 순서 효과 줄이기 | 카드 숫자를 바꾼 2세트를 만들고, 가능하면 절반은 A→B, 절반은 B→A 순서로 진행 |
| 구간별 측정 | ① 발령→전 학급 보고 완료 ② 보고 완료→전교 집계 확정 ③ 확정→학부모 안내문 완성 ④ 종료→결과보고 초안 완성 |
| 측정 도구 | A안은 진행자가 스톱워치로 재고, B안은 앱의 감사 로그 시각을 씁니다(자동 기록) |
| 함께 세는 것 | 정확성(합계 오류 건수), 재확인 연락 횟수, 입력·전사 횟수 |
| 실제 모의훈련 | 학교 승인 후 B안만 실제로 운영하고 앱 기록을 추출(실측치) |

## E. 결과 분석 방법

표본이 5\~10명으로 작아서 통계적 유의성은 주장하지 않습니다. 평균과 함께 최솟값·최댓값, 응답자 수를 항상 적습니다.

1. **시간**: 구간별 A안·B안 중앙값과 차이(분, %)를 냅니다. ‘모의 측정’이라고 표기합니다.
2. **절차**: 단계 수와 입력 횟수를 비교하는 표를 만듭니다. 사라진 단계와 새로 생긴 단계를 모두 적습니다.
3. **평가 점수**: 문항별·영역별·역할별 평균을 냅니다. 역문항(Q4, Q8)은 6에서 뺀 값으로 바꿉니다. 3.5점 미만 문항은 개선 대상으로 표시합니다.
4. **자유 의견**: ‘줄어든 업무 / 새 업무 / 불편 / 신뢰·안전 / 기능 요청’ 다섯 범주로 나눠 건수를 세고, 대표 원문을 인용합니다.
5. **종합 표현 규칙**: 앱 실측값은 ‘측정’, 탁상 비교는 ‘모의 측정’, 담당자 응답은 ‘사용자 인식’, 시간 추정은 ‘담당자 추정’으로 구분해 씁니다. 설문만으로는 ‘시간이 단축되었다’고 쓰지 않습니다.
6. **불편 지적 반영**: C의 절차로 고친 뒤 재테스트 결과를 개선 전후로 나란히 보여 줍니다.

## F. 경진대회 제출용 실증 증빙자료 구조

증빙자료는 파일 하나로 냅니다(공고문 요건). 아래 순서로 묶고, 각 자료에 ‘측정 / 모의 측정 / 사용자 인식 / 추정’ 라벨을 붙입니다.

| 순서 | 자료 | 내용 | 연결되는 서면심사 항목 |

| 1 | 실증 요약(1쪽) | 무엇을 어떻게 재었고 무엇을 주장하지 않는지 | ② 업무 활용도 |
| 2 | 업무 절차 비교표 | 기능별 기존 단계 vs 앱 단계, 사라진 단계·새 단계 | ① 문제 정의, ④ 창의성 |
| 3 | 탁상 비교 측정 기록지 | 상황 카드, A안·B안 구간별 시간과 오류 | ② |
| 4 | 모의훈련 앱 기록 | 발령·반별 보고·종료 시각(감사 로그 CSV), 상황 보고서 PDF. 학생 실명 없음 | ②, 발표심사 ①③ |

| 6 | 사용자 평가 결과 | B의 문항별 평균·범위·응답자 수, 역할별 | ② |
