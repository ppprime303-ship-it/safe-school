# SAFE SCHOOL — 학교 등록 및 교직원 가입 구조 최종 확정

기존 SAFE SCHOOL 설계에 아래 정책을 반영하고 관련 코드를 개발해 주세요.

## 1. 기본 원칙

현재 학교정보 연동에는 학교알리미 공식 공공데이터를 이용합니다.

장기적으로는 교육청 및 나이스 운영기관의 공식 승인 후 나이스에서 실제 학교·학급 재적 인원을 연동하는 것을 목표로 합니다.

현재 단계에서는 승인되지 않은 나이스 내부정보 연동을 시도하지 않습니다.

최우선 목표는 교직원과 학교안전업무 담당자의 반복 입력을 최소화하는 것입니다.

## 2. 최초 학교 등록

학교 소속 최초 가입자는 학교명을 검색하여 학교를 선택합니다.

학교알리미 공식 API에서 실제 제공하는 학교 기본정보를 가져와 학교 등록 신청을 생성합니다.

학교 식별코드로 중복 등록을 방지합니다.

최초 가입자의 이메일 인증과 별도의 관리자 자격 검증이 완료된 뒤 학교 관리 기능을 활성화합니다.

단순히 첫 가입자라는 이유로 관리자 권한을 자동 부여하지 않습니다.

관리자 자격 확인 방식이 마련되기 전에는 학교 등록을 '관리자 승인 대기' 상태로 유지합니다.

## 3. 후속 교직원 가입

기존 학교가 등록되어 있다면 신규 학교를 생성하지 않습니다.

가입자는 학교명 검색으로 기존 학교를 선택합니다.

가입 절차:
1. 학교 선택
2. 기관 이메일 입력
3. 이메일 인증
4. 기존 학교 관리자에게 가입 신청
5. 관리자 소속 확인 및 승인
6. 담당 학급·업무 권한 배정
7. 계정 활성화

학교 기본정보를 다시 입력하도록 하지 않습니다.

## 4. 학교알리미 공공데이터

공식 API 명세에서 제공 여부를 확인한 데이터만 사용합니다.

예상 조회 항목:
- 학교명
- 학교급
- 학교코드
- 소재지
- 학년별 학생 수
- 학급별 학생 수 또는 학급 규모

실제 API에서 지원하지 않는 항목은 자동조회 기능을 구현한 것으로 표시하지 않습니다.

학생·학급 규모에는 공시 기준일과 출처를 저장합니다.

학교알리미 자료를 실제 현재 재적 인원으로 무조건 확정하지 않습니다.

공시자료가 학년별 합계만 제공되는 경우 학급별 학생 수를 임의로 나누지 않습니다.

관리자가 실제 재적 인원을 일괄 확인·수정하도록 합니다.

## 5. 데이터베이스

다음 구조를 검토하고 기존 스키마에 반영합니다.

- Schools: 학교 기본정보 및 공식 학교 식별자
- SchoolRegistrations: 최초 학교 등록과 관리자 자격 확인 상태
- SchoolMemberships: 교직원별 학교 소속과 승인 상태
- Users: 사용자 계정
- Classes: 학년도별 학급 구성
- ClassAssignments: 담당 교직원과 학급
- SchoolPublicDataSnapshots: 공시자료·출처·기준일

학교 데이터는 개인 계정과 분리합니다.

공식 공시자료가 변경되어도 실제 운영 데이터와 과거 재난 보고 기록을 자동으로 덮어쓰지 않습니다.

학교별 데이터 접근 권한을 서버에서 검증합니다.

## 6. 미래 나이스 연동 준비

학교알리미, 나이스, 관리자 수동 입력의 데이터 출처를 구분할 수 있는 구조를 설계합니다.

향후 공식 승인된 나이스 연동을 추가하더라도 기존 학교, 학급, 교직원, 재난 기록을 삭제하거나 재생성하지 않도록 합니다.

학교 식별코드 간의 매핑과 데이터 갱신·충돌 처리 정책을 설계합니다.

## 7. 개발 및 검증

다음 시나리오를 테스트합니다.

1. 최초 교직원 A가 학교를 검색해 등록 신청
2. 학교알리미 공공데이터 자동 입력
3. 관리자 자격 확인 전 권한 부여 차단
4. 승인 후 학교 공간 활성화
5. 교직원 B가 동일 학교에 가입
6. 중복 학교 생성 없이 기존 학교에 연결
7. 관리자 승인 전 업무 데이터 접근 차단
8. 학급 및 담당 권한 배정
9. 공시자료 변경 시 실제 학급 데이터 보존
10. API 장애 시 기존 저장정보 이용
