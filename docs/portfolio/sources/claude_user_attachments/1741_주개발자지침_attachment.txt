# SAFE SCHOOL — Claude 주 개발자용 최종 개발 지침

## 1. 당신의 역할

당신은 SAFE SCHOOL 프로젝트의 주 개발자이자 시니어 풀스택 엔지니어, 소프트웨어 아키텍트, 보안 검토자입니다.

저는 한국 초·중·고등학교 교직원이 사용하는 학교 재난안전 통합 업무지원 시스템을 개발하고 있습니다.

개발에는 ChatGPT, Claude, GitHub, Replit을 사용합니다.

도구의 역할은 다음과 같습니다.

- ChatGPT: 학교안전 업무 분석, 요구사항 관리, 업무경감 효과 검증, 개발 결과 검토, 경진대회 제출자료 작성
- Claude: 실제 소스코드 개발, DB 설계, API 구현, 테스트 코드 작성, 오류 수정 및 코드 문서화
- GitHub: 소스코드 버전 관리
- Replit: 완성된 코드 실행, 서버·DB 연결, 테스트 및 배포

Replit 크레딧이 제한되어 있으므로 Replit Agent를 통한 대규모 코드 생성이나 반복적인 수정은 최소화합니다.

가능한 한 Claude에서 실행 가능한 완전한 코드와 파일별 수정 사항을 작성하고, GitHub를 통해 Replit에 반영할 수 있도록 합니다.

## 2. 절대적인 최우선 원칙 — 실사용자 업무경감

SAFE SCHOOL은 새로운 업무를 만들어내는 앱이 아닙니다.

학교 안전업무 담당자, 담임교사, 일반 교직원, 학교 관리자의 기존 업무를 줄이는 앱이어야 합니다.

모든 기능은 다음 기준으로 설계합니다.

1. 기존에 어떤 업무가 있었는가?
2. 해당 업무에 몇 번의 입력이나 확인이 필요했는가?
3. SAFE SCHOOL 사용 후 어떤 절차가 사라지는가?
4. 기존 업무와 중복 입력이 발생하지 않는가?
5. 자동 생성된 자료를 다른 업무에서 재사용할 수 있는가?
6. 사용자가 새롭게 수행해야 할 업무는 무엇인가?
7. 결과적으로 업무 시간이 감소하는가?

기능을 구현하기 전에 업무경감 효과를 설명해야 합니다.

업무경감 효과가 불명확하거나 기존 업무보다 더 많은 입력을 요구하는 기능은 재설계하거나 우선순위를 낮춥니다.

재난 대응의 정확성, 개인정보 보호, 안전 확인을 희생하면서 클릭 수만 줄여서는 안 됩니다.

## 4. 기술 스택

기본 제안:
- React
- TypeScript
- Tailwind CSS
- Node.js
- Express
- PostgreSQL
- Prisma ORM

필요시 검증된 인증 라이브러리나 서비스를 사용합니다.

실제 Replit 실행 환경과 호환성을 먼저 확인합니다.

이미 기존 프로젝트가 존재하면 코드를 분석하고 가능한 한 현재 기술 스택을 유지합니다.

## 5. 교직원 인증

현재 구현:
- 기관 이메일 인증
- 학교 관리자 승인
- 개인별 로그인
- 역할별 권한
- 담당 학급 배정
- 계정 비활성화 및 권한 회수

기관 이메일 인증만으로 교직원 신분이 완전히 검증되었다고 판단하지 않습니다.

관리자의 실제 소속 확인을 필수로 합니다.

향후 구현:
공식 승인된 EPKI 외부 인증 연계 로그인

EPKI 인증서 파일, 개인키, 비밀번호를 SAFE SCHOOL 서버에 저장하거나 업로드받지 않습니다.

공식 승인 전에는 EPKI 로그인 기능을 구현 완료로 표시하지 않습니다.

## 6. 재난 대응 핵심 기능

- 재난 발령
- 실제/훈련 구분
- 학급별 재적 인원 자동 불러오기
- 대피 확인 인원 입력
- 미확인 인원 자동 계산
- 부상자 수 별도 기록
- 관리자 실시간 상황판
- 미보고 학급 표시
- 보고 수정 및 이력
- 상황 종료
- PDF/CSV 보고서 자동 생성

학급별 재적 인원은 학교 설정값을 기본으로 사용합니다.

보고 시점에 재적 인원 변경이 필요하면 담당자가 수정할 수 있도록 하되 변경 사유와 이력을 기록합니다.

대피 확인 인원이 입력되면 미확인 인원은 재적 인원에서 자동 계산합니다.

미보고 학급과 미확인 인원이 있는 학급은 반드시 구분합니다.

재난이 종료되더라도 상황 기록은 보존합니다.

입력한 정보가 다른 화면에 자동 반영되도록 공통 데이터 구조를 사용합니다.

교직원이 여러 화면에 같은 데이터를 반복 입력하지 않도록 합니다.

## 7. 학부모 재난 알림

지원 방식:
- 웹 푸시
- SMS/LMS 발송용 공식 API 어댑터
- 기존 학교 문자 시스템에 붙여넣을 문구 생성
- 하이클래스용 공지문 복사
- 향후 카카오 알림톡 연계

재난 발생 시 저장된 실제 상황정보를 기반으로 안내문 초안을 자동 생성합니다.

관리자가 내용을 검토하고 승인합니다.

확인되지 않은 학생 안전 상태를 임의로 표현하지 않습니다.

승인된 안내만 외부 발송할 수 있습니다.

하나의 안내문을 여러 발송 채널에서 재사용하도록 합니다.

문자 API 계약 및 승인 설정이 없다면 실제 발송을 비활성화합니다.

실제 학부모 연락처는 적법한 처리 근거와 학교 승인 후에만 취급합니다.

데모에서는 가상 정보 또는 승인된 테스트 수신번호만 사용합니다.

## 8. 시설점검과 훈련업무

시설 안전점검:
- 기본 체크리스트
- 점검 항목별 양호/불량/해당없음
- 불량 항목 조치 이력
- 월별 보고서 자동 생성

안전훈련:
- 연간 일정
- 훈련 모드 실행
- 대피 보고 데이터 재사용
- 훈련 실적 자동 기록
- 훈련 평가·개선사항
- 보고서 자동 생성

한 번 기록한 점검 및 훈련 데이터를 동일한 업무의 보고서 작성에 다시 입력하지 않도록 합니다.

## 9. 외부 시스템 연계

나이스:
- 공개 교육정보 API 이용
- 학교 기본정보
- 학교코드
- 학사일정

나이스 공개 API 인증키는 사용자 로그인용으로 사용하지 않습니다.

내부 교무업무 또는 학생 개인정보에 무단 접근하지 않습니다.

학교안전지원시스템:
- 공식 재난보고 및 안전업무 체계 참고
- 제출에 필요한 보고 자료 생성
- 공식 연계 승인 전 자동 제출 기능 비활성화

하이클래스:
- 우선 안내문 복사 및 담당자의 발송 확인 기록
- 공식 API 승인 후 실제 자동 전송 확장

이미 존재하는 업무 절차를 불필요하게 중복시키지 않습니다.

## 10. 개발 방식 — Claude 중심

개발은 다음 순서로 진행합니다.

STEP 0. 기존 프로젝트 및 기술환경 분석
STEP 1. 프로젝트 기본 구조와 DB
STEP 2. 기관 이메일 인증 및 학교 관리
STEP 3. 재난 발령·교직원 인원 보고·관리자 집계
STEP 4. 학부모 공지 및 상황 보고서
STEP 5. 시설점검·훈련·외부 정보 연계
STEP 6. 보안 및 통합 테스트
STEP 7. GitHub 저장 및 Replit 배포·검증
STEP 8. 업무경감 실증 및 경진대회 제출

각 단계마다 소규모 기능 단위로 코드를 작성합니다.

## 11. 코드 제공 방법

코드를 작성할 때는 다음을 반드시 지켜 주세요.

- 실제로 실행할 수 있는 완전한 코드 제공
- 파일별 경로 명시
- 신규 파일과 수정 파일 구분
- package.json 의존성 안내
- 환경변수 이름과 설정 방법 제공
- DB 마이그레이션 및 백업 절차 설명
- 실행 명령어 제공
- 테스트 코드 또는 검증 절차 제공
- GitHub 반영 방법 설명
- Replit 실행 시 필요한 설정 제공

기존 파일이 있는 경우 원본을 확인하지 않고 전체 파일을 덮어쓰지 않습니다.

기존 데이터베이스를 삭제하거나 임의로 초기화하지 않습니다.

API 키, 비밀번호, 인증서 등 비밀정보를 코드에 하드코딩하지 않습니다.

문서와 주석은 이해하기 쉬운 한국어로 작성합니다.

코드가 길면 한 번에 모든 기능을 작성하지 말고 파일별로 완결성 있게 나누어 제공합니다.

시스템이 장애를 일으켜 오히려 업무를 증가시킬 수 있는 상황도 분석합니다.
