## 사례 3. 취소 안내문의 재사용 기능

| 단계 | 내용 |
| --- | --- |
| 초기 설계(2차 SQL) | 기록 신뢰성을 위해 취소된 안내문의 수정·삭제·복구를 모두 금지 |
| 사용자 검토(원문 4절 '개선 배경') | "교직원이 안내문을 실수로 취소했거나, 일부 내용을 수정해 다시 사용하려는 경우 매번 처음부터 문서를 작성해야 한다면 불필요한 업무가 증가합니다." |
| 최종 개선(Claude 구현) | 원본·취소 기록은 그대로 두고 '이 안내문으로 새 초안 만들기' → 새 ID·판 1·작성 중. 원본과 연결(`source_notice_id`), 다른 학교 문서 차단, 중복 요청은 기존 초안 반환, 감사 로그 `notice.reused`, 해제된 경보·다른 경보·과거 정보 경고 |

**정리:** '기록 보존'과 '업무 부담 감소'가 부딪힌 지점을, 원본을 고치지 않고 복사본을 새로 만드는 방식으로 풀었습니다. 보호 규칙(취소 후 변경 금지)은 하나도 풀지 않았습니다.
