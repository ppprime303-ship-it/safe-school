## 2. 원인과 수정(정리)

**원인(확정)**
1. 재송출 묶음은 경보 **수집 때만** 계산했습니다. 시연 학교 주소(`인천광역시 가상 테스트 주소`)로는 시군구를 알 수 없어 수집 때 2건 모두 '미판정'이었고, 소재지를 확인하자 두 건 모두 '대상'으로 바뀌면서 묶음 없이 따로 표시됐습니다.
2. '해제됨'은 해제 경보가 직접 가리키는 1건에만 붙었고, 해제 경보 자체에는 '해제' 표시가 붙어 화면에서 비슷하게 보였습니다. 그래서 3건 중 2건에 표시가 보이고 1건(재송출 경보)에는 없었습니다.

**수정**
- `server/src/alerts/grouping.ts`(새 파일): 재송출 묶음 함수 하나로 통일. 같은 학교 · 판정 '대상' · 같은 공급자 · 같은 내용 해시 · 묶음 첫 경보 후 6시간 이내. 경보 수집, 소재지 재판정, 기존 데이터 정리가 모두 이 함수를 씁니다. 반복 실행해도 결과가 같습니다.
- `server/src/alerts/collector.ts`: 수집 때도 같은 함수 사용.
- `server/src/services/alerts.ts`: 소재지 확인 후 묶음 정리(결과·감사 로그에 `regrouped`), 해제 경보가 묶음 안 어느 경보를 가리켜도 대표 경보에 '해제됨', 묶음 중 하나라도 읽으면 읽음(사용자별).
- `scripts/alerts.ts`: `npm run alerts -- regroup`(점검만) / `--apply`(정리). 학교별 판정 기록만 바꾸고 경보 원문은 그대로, 감사 로그 남김.
- `client/src/lib/alerts.ts`: 해제·정정 경보 표시를 '해제 안내'·'정정 안내'로 바꿔 '해제됨'과 구분.
