재난 유형:

- 미세먼지
- 지진

- 화재·가스

예시 유형:

- 학부모 발령 안내
- 교직원 발령 안내
- 해제 또는 상황 종료·안전 확인 안내

교사는 예시문 카드를 클릭하여 제목과 본문을 편집 영역에 불러옵니다.

기존에 작성 중인 문안이 있으면 덮어쓰기 확인을 요구합니다.

예시 원본은 변경하지 않으며, 저장되는 것은 교사가 수정한 안내문입니다.

학교명·경보 유형·발령 시각·지역 등 확인된 정보만 자동 채웁니다. 확인되지 않은 학교 조치나 문의처는 입력 안내로 남깁니다.

- 주요 변경 및 재사용 행위 감사 기록

### C3. 안내문 활용 기능

- 제목 복사
- 본문 복사

- 안내문 미리보기

처리 이력의 발송 채널과 일시는 교직원이 직접 기록하는 값이며, 실제 발송 성공·수신 확인 또는 K-에듀파인 공식 결재 완료를 뜻하지 않습니다.

실제 학부모 연락처는 저장하지 않습니다.

## 4. 추가 개선 기능 — 취소된 안내문으로 새 초안 만들기

이번 통합 지시서에서 새로 확정한 요구사항입니다.

### 개선 배경

현재 2차 SQL은 취소된 안내문의 수정·삭제·복구를 차단합니다.

이 정책은 기록의 신뢰성을 위해 유지합니다.

그러나 교직원이 안내문을 실수로 취소했거나, 일부 내용을 수정해 다시 사용하려는 경우 매번 처음부터 문서를 작성해야 한다면 불필요한 업무가 증가합니다.

따라서 **취소 기록은 보존하면서 기존 내용을 새로운 안내문으로 복사하는 기능**을 추가합니다.

### 최종 정책

- 취소된 안내문의 원본 수정: 금지
- 원본 삭제: 금지
- 취소 상태 직접 복구: 금지
- 취소 사유·시각 보존: 필수
- 취소된 안내문 조회 및 복사: 허용
- 취소된 안내문으로 새 초안 생성: 허용
- 새 초안의 수정·저장·복사: 허용

### 사용자 화면

취소된 안내문에 다음 단추를 추가합니다.

**'이 안내문으로 새 초안 만들기'**

동작 순서:

1. 교직원이 취소된 안내문을 선택합니다.
2. 기존 안내문의 제목과 본문을 불러옵니다.
3. 기존 안내문과 별개의 새 ID로 초안을 생성합니다.
4. 새 초안의 상태는 `draft`, 판 번호는 1로 시작합니다.
5. 교사가 내용을 수정하고 저장할 수 있습니다.
6. 기존 미리보기와 복사 기능을 이용할 수 있습니다.

기존 취소 문서의 내용과 기록은 변경되지 않아야 합니다.

### 재사용 이력 추적

기존 안내문과 새 초안의 관계를 추적할 수 있도록 설계합니다.

`source_notice_id` 등의 선택적 연결 컬럼이 적절한지 검토해 주세요.

다음 조건을 충족해야 합니다.

- 원본과 새 초안은 서로 다른 ID
- 원본 취소 기록 유지
- 새 초안은 별도 수정 이력 시작
- 재사용한 사용자와 시각을 감사 로그에 기록
- 다른 학교 문서 재사용 차단
- 같은 재사용 요청의 중복 실행 방지

기존 마이그레이션은 어느 Replit DB에도 적용되지 않았으므로, 필요한 경우 현재 SQL 초안을 수정할 수 있습니다.

새 테이블을 불필요하게 추가하지 말고 기존 구조를 우선 활용해 주세요.

### 경보 상태 및 연결 정책

과거 안내문에 연결된 경보가 이미 해제됐을 수 있습니다.

이 경우 새 초안을 만들 때 다음 조건을 적용합니다.

1. 연결된 경보의 상태를 확인합니다.
2. 해제된 경보에 연결한 채 재사용하는 경우 명확한 경고를 표시합니다.
3. 과거 발령 시각과 지역을 현재 경보처럼 표시하지 않습니다.
4. 다른 경보에 연결하려면 새로운 경보가 해당 학교의 대상 경보인지 검증합니다.
5. 학교 조치 사항과 안내 시점은 교사가 최종 확인하도록 합니다.
6. 새 경보에 연결하는 경우에도 공식 경보 원문은 변경하지 않습니다.

## 5. 최종 DB 및 서비스 보안 요구사항

기존 2차 SQL의 다음 보호 규칙은 반드시 유지합니다.

- 같은 학교의 대상 경보만 안내문에 연결
- 재송출 경보는 대표 경보로 연결
- 처리 이력과 안내문 학교 소속 일치
- 취소 후 원본 변경·복구 차단
- 안내문 삭제 금지
- 판 번호 증가 및 수정 이력 자동 기록
- 학교·경보·작성자 등 핵심 연결 정보의 임의 변경 금지
- 공식 재난경보 원문 수정·삭제 금지

추가하는 재사용 기능은 기존 보호 규칙을 우회하면 안 됩니다.

서비스와 API에서는 학교 소속·승인 상태·역할을 항상 확인하고, 타 학교 문서 ID를 통한 조회·복사·재사용을 차단해야 합니다.
