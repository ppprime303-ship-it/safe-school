# Ⅱ. 개발 과정 및 실제 AI 협업 기록

## 1. STEP 3-C 실제 브라우저 기능 검증

### 1-1. 재난경보와 안내문 작성 기능 연계 확인

기존 STEP 3-B에서 구현한 모의 재난경보 관리 기능을 이용하여 안내문 작성 화면에 진입하였습니다.

**실제 대화 기록**

사용자:

> 해제된 폭염정보 맞지¿

ChatGPT:

> 응, 맞아! 재난경보함에서 '해제됨'이라고 표시된 기존 폭염경보를 선택하면 돼.

사용자:

> 응열리고 이미 해제되었다는 주의도 표시되

이를 통해 이미 해제된 재난경보에서 안내문을 작성할 경우, 해당 경보가 종료되었음을 알리는 주의 문구가 표시되는 것을 확인하였습니다.

이는 과거의 경보 정보를 현재 유효한 정보로 오인하는 일을 방지하기 위한 기능입니다.

### 1-2. 상황별 예시문 불러오기

재난 유형과 안내 대상에 따라 미리 준비된 예시문을 선택하고, 편집 화면에 제목과 본문이 정상적으로 반영되는지 확인하였습니다.

사용자:

> 제목과 본문이 정상적으로 나와

**검증 결과**

- 상황별 안내문 예시 불러오기 정상
- 제목 및 본문 편집 영역 표시 정상
- 기존 재난경보와 연결된 안내문 작성 화면 정상

### 1-3. 안내문 작성 및 저장

예시문 본문에 테스트 문구를 추가하여 실제 저장 기능을 검증하였습니다.

**테스트 입력 문구**

`[시연 테스트] SAFE SCHOOL 안내문 작성 기능 확인`

저장 과정에서 사용자는 다음과 같이 질문하였습니다.

사용자:

> 작성완료로 저장 버튼을 눌러야 하나¿

ChatGPT는 작성 완료가 앱 내부의 문안 상태를 의미하며, 학교의 공식 결재 완료 또는 실제 발송을 의미하지 않는다는 점을 안내하였습니다.

사용자:

> 저장했습니다 가 떠

이후 페이지를 새로고침하여 작성 상태와 저장 내용의 유지 여부를 확인하였습니다.

사용자:

> 응 작성완료가 유지되어있어

**검증 결과**

- 안내문 저장 성공
- 저장 완료 메시지 정상 표시
- 페이지 새로고침 후 작성 완료 상태 유지
- 작성 데이터의 재조회 정상

### 1-4. 수정 이력 관리 검증

기존 안내문을 다시 편집한 후 저장하여, 수정 전후의 판본과 이력이 정상적으로 기록되는지 확인하였습니다.

**테스트 입력 문구**

`[수정 테스트] 안내문 수정 이력 확인`

사용자:

> 응 모두 표시되고 있어

**검증 결과**

- 안내문 재수정 가능
- 수정 이력 표시 정상
- 이전 판과 변경된 판의 기록 확인

## 2. 실제 사용 중 UI 문제 발견

안내문 수정 이력을 확인하던 중 사용자가 저장 버튼의 역할이 직관적이지 않다는 문제를 제기하였습니다.

### 2-1. 최초 문제 제기

사용자:

> 근데 저장 작성완료로 저장과 작성중으로 바꿔 저장 기능이 나뉘어있는 이유를 모르겠어

초기 대화에서는 작성 중과 작성 완료 상태를 구분하기 위한 버튼 구조라고 이해하였습니다.

그러나 사용자는 실제 화면의 구성을 추가로 설명하였습니다.

사용자:

> 응 지금 저장 칸은 따로있고 、 작성중으로 저장 ㅡ 작성완료 저장는 상태에 따라 번갈아 나오는게 따로 있어서 저장 버튼이 두개야

이 설명을 통해 사용자가 불편하게 느낀 부분은 단순한 상태 구분이 아니라, **일반 저장 버튼과 상태 변경을 동반한 저장 버튼이 별도로 존재한다는 점**임을 파악하였습니다.

### 2-2. 문제 분석

기존 화면에는 다음 저장 기능들이 존재하였습니다.

- 「저장」
- 「작성 완료로 저장」
- 「작성 중으로 바꿔 저장」

Claude의 후속 분석에 따르면 이 버튼들은 동일한 안내문 수정 API를 호출하면서 작성 상태 값만 다르게 전달하는 구조였습니다.

따라서 서버 기능을 재개발하지 않고도 UI 구조를 개선할 수 있다고 판단하였습니다.

### 2-3. 개선 방향 결정

사용자의 문제 제기를 바탕으로 다음과 같이 개선 방향을 정하였습니다.

**개선 전**

여러 저장 버튼 중 원하는 동작을 선택해야 하는 방식

**개선 후**

작성 상태는 별도로 선택하고, 실제 저장은 「저장하기」 버튼 하나로 수행하는 방식

아울러 예시문 선택 영역과 수정 이력 표시를 단순화하고, 취소 버튼을 일반 저장 기능과 시각적으로 분리하도록 계획하였습니다.

**개발 관점의 의의**

이번 개선은 새로운 기능을 추가하는 것이 아니라, 실제 사용 과정에서 발견한 업무상의 불편을 해결하기 위한 수정이었습니다.

기술적 기능의 완성도와 실제 사용 편의성은 서로 다른 평가 대상이며, 기능이 정상 작동하더라도 사용자 경험을 개선할 필요가 있음을 확인하였습니다.

> 응 취소되었어

### 3-2. 취소된 안내문으로 신규 초안 생성

확인 사항은 다음과 같습니다.

- 새 안내문의 상태가 작성 중으로 표시되는지

### 3-3. 취소된 원본 보존 확인

사용자:

**검증 결과**

- 안내문 취소 정상

이 시점에서 STEP 3-C의 주요 기능이 정상적으로 작동한다는 점을 확인하였으며, UI 개선을 별도 작업으로 진행하기로 하였습니다.

## 2. 실제 Claude 전달 프롬프트

다음은 당일 대화에서 작성한 Claude 전달용 프롬프트입니다.

### 프롬프트: SAFE SCHOOL STEP 3-C UI/UX 개선 요청

**1. 현재 개발 및 검증 상태**

SAFE SCHOOL은 초등학교 교사의 재난 대응 업무를 지원하는 웹앱입니다.

STEP 3-C(재난안전 안내문 작성 지원 및 교사 직접 발송)의 주요 기능 구현이 완료되었으며, Replit 브라우저에서 다음 사항을 직접 확인했습니다.

- 재난경보함에서 안내문 편집 화면 진입
- 해제된 재난경보에 대한 주의 문구 표시
- 상황별 안내문 예시 선택 및 제목·본문 불러오기
- 안내문 작성, 수정, 저장
- 새로고침 후 작성 상태 유지
- 수정 이력 및 판 번호 관리
- 안내문 취소
- 취소된 안내문으로 새 초안 생성
- 기존 취소 원본의 보존

기존 자동화 테스트는 총 275개 통과했습니다. 이는 UI 수정 전 검증 결과이며, 변경 후 재검증이 필요합니다.

**이번 요청의 핵심은 기능 추가가 아닌 UI/UX 단순화입니다.**

**2. 개선 목표**

교사가 재난 상황에서도 안내문을 빠르게 작성하고, 복사하고, 기존 학교 발송 체계에서 활용할 수 있도록 화면을 직관적으로 개선해 주세요.

다음 원칙을 준수해 주세요.

1. 기존 기능과 데이터 구조를 최대한 유지합니다.
2. 화면에서 중복되는 조작 요소를 줄입니다.
3. 위험한 작업(취소 등)은 일반적인 저장 작업과 명확하게 구분합니다.
4. 작업 상태와 실제 발송 여부를 혼동하지 않도록 합니다.
5. 관리자와 교사 모두 쉽게 사용할 수 있어야 합니다.
6. 모바일과 PC 화면 모두 고려합니다.

**3. 필수 개선 사항**

**A. 중복 저장 버튼 통합 — 최우선**

현재 안내문 편집 화면에는 일반적인 '저장' 버튼과, 상태에 따라 번갈아 나타나는 '작성 중으로 저장' 또는 '작성 완료로 저장' 버튼이 별도로 존재합니다.

사용자 입장에서는 어떤 버튼을 눌러야 할지 혼란스러울 수 있습니다.

다음과 같이 개선해 주세요.

- 본문의 편집 내용을 저장하는 버튼은 '저장하기' 하나로 통일
- '작성 중'과 '작성 완료'는 별도의 명확한 작성 상태 선택 UI로 제공
- 저장 시 현재 선택된 작성 상태를 함께 반영
- 저장 성공 여부는 간결한 메시지로 표시
- 최초 저장과 이후 수정 저장 모두 직관적으로 처리
- 기존 수정 이력, 판 번호, 동시 수정 충돌(409), 감사 기록 기능 유지
- 사용자가 상태를 변경하지 않고 본문만 수정한 경우에는 기존 작성 상태 유지

단, 실제 코드에서 '저장' 버튼과 상태 전환 버튼이 서로 다른 기능을 담당하고 있다면 먼저 구현과 API 동작을 분석하고, 데이터 손실이나 의도치 않은 상태 변경이 발생하지 않는 설계를 선택해 주세요.

**B. 안내문 예시 선택 영역 간소화**

현재 제공되는 7개 재난 유형 × 3개 상황별 예시문, 총 21개 예시는 모두 유지해 주세요.

다만 한 화면에서 너무 많은 정보가 동시에 노출되지 않도록 개선해 주세요.

추천 방향:

- 재난 유형 선택
- 상황 선택: 학부모 발령 안내 / 교직원 발령 안내 / 해제 및 안전 확인
- 선택한 예시문 미리보기 및 적용

가능하다면 현재 연결된 경보의 재난 유형을 기본값으로 사용해 주세요.

기존 안내문을 수정한 상태에서 다른 예시문을 적용하면 내용이 덮어써질 수 있으므로, 기존 덮어쓰기 경고 및 확인 절차를 유지해야 합니다.

**C. 편집 화면의 정보 구조 정리**

다음 순서로 화면의 중요도를 조정해 주세요.

1. 현재 안내문 제목과 작성 상태
2. 해제·취소된 경보 등 필수 주의 문구
3. 예시문 선택
4. 제목 및 본문 편집
5. 저장 및 복사 기능
6. 수정 이력, 처리 기록 등 부가 정보

수정 이력이나 처리 기록처럼 자주 사용하지 않는 영역은 기본적으로 접힌 형태로 제공하는 방식을 검토해 주세요.

현재 기능의 접근성이 떨어지지 않도록 주의해 주세요.

**D. 버튼 명칭과 동작의 명확화**

교사가 버튼의 결과를 예측할 수 있도록 명칭을 정리해 주세요.

예시:

- 저장하기
- 제목 복사
- 본문 복사
- 전체 안내문 복사
- 이 안내문으로 새 초안 만들기
- 안내문 취소

일반적인 저장·복사 기능은 쉽게 찾을 수 있게 하고, 취소와 같은 중요한 작업은 시각적으로 분리해 주세요.

'작성 완료'는 앱 내 문안 작성 상태일 뿐이며, 공식 결재 완료나 실제 발송을 의미하지 않습니다.

**E. 모바일 및 접근성**

- 작은 화면에서도 제목, 본문, 주요 버튼이 읽기 쉬울 것
- 버튼 중복 클릭 및 실수 방지
- 키보드 조작과 포커스 표시 고려
- 상태를 색상만으로 구분하지 않을 것
- 경고 문구의 가독성 유지

**4. 절대 변경하면 안 되는 기능 및 정책**

이번 UI 개선에서 다음 기능과 정책을 유지해 주세요.

- 학교 간 데이터 격리

- 확인된 학교 정보와 모의 경보 정보의 자동 반영
- 확인되지 않은 학교 조치 사항 및 연락처를 임의 생성하지 않음

- 정성적 기대효과
- 파급효과 및 확산가능성
- 유지보수 계획
- 기능 고도화 계획
- 타 시스템 연계 검토
- 학교의 협조 및 지원 요청 사항

특히 제안서에서는 프로그램이 단순히 재난정보를 제공하는 것이 아니라, **재난 대응과 학교 안전관리 업무의 효율화를 지원하는 시스템**이라는 점을 강조하였습니다.

### 2. 학교에 요청할 지원 사항

교장·교감선생님께 기능을 시연하고 관리자 관점의 사용성 및 현장 적용 가능성에 대한 의견을 수렴하고자 합니다.

학교 안전업무 담당자에게는 재난 대응 및 문서 작성 과정의 업무경감 가능성을 검토받고자 합니다.

일반 교직원에게는 학급별 대피 인원 입력 및 재난정보 확인 기능의 편의성을 평가받고자 합니다.

### 3. 간소화된 사용자 평가 계획

교직원의 업무 부담을 최소화하기 위해 다음과 같이 구성하였습니다.

- 평가 대상: 학교 관리자, 안전업무 담당자, 희망 교직원
- 예상 참여 인원: 5~8명 내외
- 기능 시연: 약 5분
- 간편 설문: 약 2~3분
- 평가 자료: 개인정보가 포함되지 않은 모의 데이터
- 평가 방법: 자율 참여 및 익명 설문

주요 평가 항목은 사용 편의성, 업무경감 기대 수준, 재난 대응 지원 가능성 및 실제 활용 의향입니다.

평가 결과가 확보되기 전까지는 업무시간 단축률 등의 정량적 성과를 확정적으로 제시하지 않기로 하였습니다.

**기록 기준일 현재 사용자 평가 계획서와 설문 문항을 작성한 단계이며, 학교 교직원의 실제 평가 결과는 아직 확보되지 않았습니다.**

또한 AI가 코드를 작성하더라도 실제 업무 요구사항의 적합성과 최종적인 기능 확인은 사용자가 직접 수행해야 한다는 점을 확인하였습니다.
