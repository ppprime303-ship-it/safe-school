# 07. 경진대회 제출용 요약 — SAFE SCHOOL

**학교 재난안전 통합 업무지원 시스템** · 2026-10-22 기준 · 개발 단계(정식 운영 승인·보안 인증 없음)

## 한 줄 소개
재난·훈련 때 **학급별 대피 보고를 모바일로 모으고**, 학교 전체 현황을 한 화면에서 확인하며, 훈련이 끝나면 **비상대피훈련일지를 한글(HWPX) 문서로 자동 작성**하는 교직원용 웹 서비스입니다.

## 문제 → 해결
| 학교 현장 문제 | SAFE SCHOOL의 해결 | 상태 |
| --- | --- | --- |
| 학급별 대피 인원·부재·부상·미확인을 구두로 모아 다시 정리 | 발령 즉시 담임 화면에 담당 학급 보고가 열리고, 미확인 인원 자동 계산 | 구현·자동 검증 |
| 전체 현황 파악이 늦음 | 상황판: 학급별 보고·미보고·미확인·부상 5초 갱신 | 구현·자동 검증 |
| 훈련 후 일지 작성 반복 | 종료된 모의훈련 기록으로 일지 자동작성, 미보고는 0명이 아닌 '미보고', 판 번호·이력 보존, HWPX 출력 | 구현·자동 검증, 한컴오피스 열람 확인 |
| 역할이 겸임·교체되는 학교 업무 | 교장·교감 직책 + 안전업무 담당·앱 운영담당 업무(겸임) 권한 | 구현·자동 검증 |
| 공식 경보와 학교 안내 | 경보 수집·지역 매칭·경보함, 안내문 작성 지원 | 모의 경보로만 확인(실제 API 미연동) |

## AI 협업 개발
- **개발자(학교 교직원)**: 문제 정의, 요구사항·우선순위·권한 정책 결정, 결과 실행·확인, 승인
- **ChatGPT**: 요구사항·SQL 검토, 오류 원인 분석, 지시서 작성
- **Claude**: 설계·코드·테스트·문서 작성
- **Replit**: 실제 DB에서 테스트·시연
- 진행 방식: 설계 → 검토 → 승인 → 구현 → 실행 검증 → 개선. 실행하지 않은 테스트는 '미실행'으로 기록

## 대표 문제 해결
1. 같은 경보가 두 번 보이던 문제 → 사용자가 실제 순서로 재현, 묶음 계산 통일(`6667a81`)
2. 다른 학교 경보와 안내문이 연결될 수 있던 SQL → DB 적용 전 검토로 차단(`69b14bd`)
3. 동시 해제로 운영 권한자가 0명이 되던 경쟁 상태 → 학교 단위 잠금(`dfe3cb4`)
4. 학교 결재 흐름과 겹치는 기능 제안 → 개발자가 범위를 줄이고 예시문·재사용 기능으로 대체(10/21)

## 한계와 계획
- 한계: 실제 학교 사용자 검증·업무경감 측정 전, 모바일 문서 미리보기 가로 스크롤, 공식 경보 API 미연동
- 계획: STEP 3-E 통합 안정화 → 제출(11/10) → 학교 협의 후 사용성 검토 → 보안·개인정보 점검
- 원칙: 실제 개인정보·학교 공식 시스템 연동은 별도 승인 없이 진행하지 않음, 학부모 외부 발송·자동 결재 기능 없음
