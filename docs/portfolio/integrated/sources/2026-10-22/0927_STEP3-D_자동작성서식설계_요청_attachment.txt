# SAFE SCHOOL — STEP 3-D 자동작성 서식 설계 및 시제품 제작 요청

## 0. 가장 중요한 작업 원칙

이번 요청은 STEP 3-D 전체 기능을 즉시 개발하라는 요청이 아닙니다.

**반드시 2단계로 분리하여 진행해 주세요.**

- **1차 작업:** 실제 학교 문서를 분석하고 자동작성 서식의 시제품을 제작하여 사용자가 직접 검토할 수 있도록 제공합니다.
- **2차 작업:** 사용자가 서식을 검토하고 명시적으로 승인한 후 실제 SAFE SCHOOL 앱 기능을 개발합니다.

이번 요청에서는 **1차 작업까지만 수행**해 주세요.

사용자 승인 없이 서버 코드, DB, 마이그레이션, 기존 STEP 3-A~C 기능을 수정하거나 Replit에 병합하지 마세요.

## 1. 프로젝트 개요

프로젝트명: SAFE SCHOOL

목표: 학교 재난 대응 및 안전관리 업무를 통합적으로 지원하고 교사의 반복적인 행정업무를 줄이는 웹 기반 시스템 개발

현재 개발 현황:

- STEP 1: 시스템 및 DB 설계 완료
- STEP 2: 학교 등록 및 사용자 권한 관리 완료
- STEP 3-A: 재난 대응 이벤트 및 학급별 대피 인원 관리 완료
- STEP 3-B: 모의 재난경보 관리 완료
- STEP 3-C: 재난안전 안내문 작성·이력 관리 및 UI 개선 완료
- UI 개선 후 자동화 테스트: 283건 통과
- 다음 단계: STEP 3-D 재난 대응 보고서 및 훈련일지 자동작성

개발 환경: React, TypeScript, Node.js, Express, Prisma, PostgreSQL, Replit, GitHub

학교의 실제 안전관리 업무 절차를 존중하고, 기존 K-에듀파인 결재체계를 대체하지 않는 것을 원칙으로 합니다.

## 2. 참고할 실제 학교 문서

다음 4개 HWP 문서를 함께 제공합니다.

1. `2026년 5월 재난대응 통합훈련 실시 계획.hwp`
2. `2026학년도 9월 비상대피훈련일지(지진).hwp`
3. `2026학년도 9월 재난대응훈련(지진) 계획.hwp`
4. `2026학년도 유치원 4월 황사·미세먼지 대응교육 및 훈련일지.hwp`

**최우선 참고 문서는 2번 비상대피훈련일지입니다.**

4개 문서는 모두 학교 안전업무 문서의 실제 사례입니다. 단, 이 문서들이 모든 교육기관에 공통으로 적용되는 법정 표준 서식이라고 가정하지 마세요.

HWP 파일을 직접 읽기 어렵다면 내용을 추측하지 말고, 필요한 파일을 HWPX 또는 PDF 등 분석 가능한 형식으로 변환해 달라고 요청해 주세요.

실제 파일에서 확인할 수 있는 항목과 향후 추가하면 좋을 항목을 명확하게 구분해 주세요.

학교 담당자 실명, 전화번호, 서명, 개인정보 등을 공개 저장소나 기본 예시 데이터에 포함하지 마세요.

## 3. 1차 작업 목표 — 자동작성 서식 설계

다음 세 종류의 서식을 분석하고 구분해 주세요.

### A. 비상대피훈련일지 — 우선 개발 대상

첨부된 실제 훈련일지의 다음 구성 요소를 최대한 유지해 주세요.

- 문서 제목
- 학교명
- 훈련 실시 일시
- 참가 인원
- 역할 및 담당 업무
- 훈련 내용
- 대피 장소
- 대피 소요 시간
- 평가 항목
- 평가 결과(O/X)
- 비고 및 평가 의견
- 향후 훈련 시 반영 사항
- 활동 사진 첨부 영역

이 문서를 STEP 3-D의 첫 번째 자동작성 서식으로 설계합니다.

### B. 황사·미세먼지 교육 및 훈련일지 — 확장 서식

대피가 중심이 아닌 환경재난·안전교육 활동의 결과 기록 서식으로 분석해 주세요.

훈련 유형에 따라 평가 항목과 훈련 내용이 달라질 수 있도록 확장 방안을 설계합니다.

단, 이번 1차 시제품은 A 서식을 중심으로 제작해 주세요.

### C. 재난대응훈련 실시 계획서 — 후속 개발 대상

지진·화재·민방공 관련 훈련 계획서에서 다음 항목을 분석해 주세요.

- 훈련 목적과 개요
- 훈련 일시 및 장소
- 대상 및 훈련 내용
- 시간별 훈련 시나리오
- 담당자별 역할 및 업무분장
- 대피 동선과 장소
- 가정통신문 등 붙임문서

계획서 자동작성은 추후 고도화할 기능으로 분리해 주세요.

## 4. 자동 입력 항목과 직접 입력 항목 구분

STEP 3-A의 현재 실제 코드와 데이터 모델을 먼저 확인해 주세요.

자동작성 기능에서 사용할 데이터를 다음 세 가지로 구분해 주세요.

**① 시스템 기록으로 확인된 정보**

예시:

- 학교명
- 훈련 또는 재난 이벤트 유형
- 이벤트 시작·종료 시각
- 학급별로 제출한 대피 현황
- 이벤트에 실제로 기록된 대응 이력

이 정보는 코드 및 DB에서 존재 여부를 확인한 다음 자동 반영 대상으로 분류해 주세요.

**② 기록이 있으면 자동 입력할 수 있는 정보**

예시:

- 대피 장소
- 대피 시작·완료 시각
- 대피 소요 시간
- 역할 담당자
- 교직원 참가 인원

현재 DB에 없거나 정보가 불완전하면 자동으로 만들어 넣지 마세요.

**③ 반드시 교직원이 직접 확인해야 하는 정보**

예시:

- 대피의 신속성 및 안전성 평가
- 방송·사이렌 작동 적절성
- 대피 동선의 문제점
- 부상 여부 및 추가 조치
- 종합 평가
- 향후 개선 사항
- 활동 사진

**AI가 관찰하지 않은 사실이나 담당자의 평가를 임의로 생성하지 마세요.**

특히 다음 사항을 준수해 주세요.

- 미보고 학급은 0명으로 표시하지 않고 '미보고'로 표시
- 재적 인원과 실제 참가 인원을 혼동하지 않음
- 보고된 인원의 중복 집계를 방지
- 참가 여부가 확인되지 않은 교직원은 임의로 참가 처리하지 않음
- 대피 소요 시간은 기준 시각이 확인되는 경우에만 계산
- 실제 재난 상황과 모의훈련을 구분
- 기록에 없는 조치 내용을 완료한 것으로 작성하지 않음

## 5. 사용자가 직접 검토할 시제품 제작

**이번 작업에서 가장 중요한 산출물입니다.**

Claude 환경에서 직접 열어보고 확인할 수 있는 자동작성 서식 시제품을 제작해 주세요.

시제품은 실제 SAFE SCHOOL 앱에 아직 연결하지 않습니다.

### 시제품에 반드시 포함할 요소

1. 실제 비상대피훈련일지를 참고한 A4 문서형 미리보기
2. 제목, 일시, 인원, 훈련 내용, 평가표 등 실제 서식의 주요 구성
3. 가상의 학교와 훈련 데이터를 이용한 자동 입력 예시
4. 자동 입력 항목과 교직원 확인 항목의 구분
5. 직접 수정해야 하는 항목을 쉽게 알아볼 수 있는 표시
6. 평가 결과 O/X 선택 예시
7. 향후 개선 사항 입력 영역
8. 활동 사진 첨부 영역
9. 인쇄했을 때 A4 문서로 읽기 좋은 배치
10. K-에듀파인에서 활용할 문서 내보내기 가능성 및 제약 안내

### 우선 제작할 시제품 형태

가능하면 **미리보기 가능한 독립형 HTML 시제품**을 제작해 주세요.

또한 환경에서 지원한다면 PDF 형태의 미리보기 문서도 함께 제공해 주세요.

사용자가 Claude에서 화면이나 파일을 직접 확인할 수 있어야 합니다.

만약 HTML 미리보기 또는 PDF 파일 생성이 환경상 불가능하다면, 가능한 대체 방식과 제약을 정확히 설명해 주세요.

### 시연 데이터

실제 학생 정보는 사용하지 마세요.

다음과 같은 가상 데이터를 사용할 수 있습니다.

- 학교명: SAFE SCHOOL 시연초등학교
- 훈련 유형: 지진 대피훈련
- 학급: 1학년 1반, 1학년 2반, 2학년 1반
- 학급별 재적 인원: 25명, 27명, 24명
- 실제 참가 인원: 임의로 확정하지 말고 '확인 필요' 또는 명시된 모의 보고 결과로 구분

실제 학교 문서의 담당자 실명이나 연락처를 재사용하지 마세요.

## 6. HWP / HWPX 및 K-에듀파인 호환성 설계

사용자의 최종 목표는 **생성된 문서를 학교에서 사용하는 한글 문서 서식으로 활용하고 K-에듀파인 결재문서에 첨부할 수 있도록 만드는 것**입니다.

다음 사항을 조사하고 설계해 주세요.

1. 원본 HWP 서식의 표와 문단 구조를 어느 정도 유지할 수 있는지
2. HWPX 파일 생성 또는 내보내기 방안
3. HWPX 직접 생성이 어려운 경우의 현실적인 대안
4. DOCX, PDF 등 보조 출력 형식의 필요성
5. 문서를 한글에서 열었을 때 편집 가능성을 확보하는 방법
6. 실제 생성 파일에 대한 호환성 검증 방법

**구현·검증하지 않은 파일 형식의 호환성을 보장한다고 표현하지 마세요.**

K-에듀파인 내부에 자동으로 파일을 업로드하거나 결재를 상신하는 기능은 이번 개발 범위에 포함하지 않습니다.
