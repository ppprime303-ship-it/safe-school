**현재 판정**
- **G1:** 조건부. L 방식은 2번 승인과 3·9번 리허설을 마치면 진행 가능합니다. V 방식은 5~7, 10, 12, 13, 20번이 남아 11/3에는 권장하지 않습니다.
- **G2:** **No-Go.** 14~20번이 남아 있습니다.

## 2. 판정 절차

1. 후보 커밋을 고정하고 커밋 해시를 적습니다.
2. 표의 필수 항목에 근거(CI URL, 기록 파일, 승인자와 날짜)를 채웁니다. 실제 이름·이메일은 저장소에 적지 않습니다.
3. 필수 항목이 하나라도 ❌·⚠️·⛔이면 No-Go입니다. 예외는 사용자가 위험을 수용했음을 적어야 합니다.
4. 판정 결과를 `docs/devlog`에 남깁니다.

## 3. 배포 당일 중단 기준

- 대상 스키마·DB·건수가 예상과 다릅니다.
- 백업이 실패하거나 읽히지 않습니다.
- 마이그레이션이 실패합니다.
- Prototype 상태 값이 설치 전 기록과 달라집니다.
- 스왑이 계속 늘거나 앱이 반복 재시작합니다.

중단하면 `beta-environment.md` 5절과 `backup-restore.md`를 따르고, `migrate reset`·스키마 DROP·강제 Push는 하지 않습니다.
