## 3. A. Beta 환경 전체 폐기 절차(미실행)

**실행 전 사용자 승인 필수.** 삭제를 되돌릴 수 없습니다.

1. 학교가 보관해야 할 보고서를 내려받아 학교 체계에 넘겼는지 확인합니다.
2. 예정일을 참여자에게 알립니다.
3. 건수만 기록합니다(이름·이메일 제외).
4. 사용자가 대상 목록(DB 이름, 폴더 경로)을 승인합니다.
5. Beta 서비스를 중지·해제합니다.
6. `safeschool_beta` DB와 `ss_beta` 계정을 삭제합니다. **`safeschool` DB·`ss_pilot`은 대상이 아닙니다.**
7. 사진 폴더, 백업 폴더, 서버 밖 사본을 삭제합니다.
8. `beta.env`, Caddy 블록, Beta 로그를 정리합니다.
9. 결과를 대조해 학교에 알리고 기록합니다.

남는 것: 이미 내려받은 파일, 외부 메일 기록, 로그 만료 전 부분, 저장 장치에서의 물리적 복구 가능성.

## 4. B. 계정 가명 처리 설계(미구현)

한 트랜잭션에서 처리하고, 학교 관리자가 아니라 운영자가 승인 후 실행합니다.

| 처리 | 내용 |
|---|---|
| `users` | 이메일을 복구 불가능한 값으로, 성명을 '삭제된 교직원'으로, 비밀번호 제거, 상태 비활성 |
| 인증 자료 | 세션, 인증코드, 로그인 식별 삭제 |
| 소속 | 회수 절차 재사용, 신청 메모 비움 |
| 소재 | 대상과 보관 기간 결정에 따라 삭제 |
| 감사 | 처리 사실을 건수·계정 ID로만 기록 |

**한계(고지 필요)**
- 보고서 스냅숏, 자유 기재, 사진, 감사 기록의 정정 전 성명에 이름이 남을 수 있습니다.
- 마지막 관리자는 먼저 이양해야 합니다.
- 개발 시 자동 테스트와 가상 DB 시험이 먼저이며, 실제 DB에는 승인 후 실행합니다.

## 5. 검토했으나 권장하지 않는 방식

| 방식 | 문제 |
|---|---|
| 사용자 행 실제 삭제 | 감사 기록 RESTRICT에 막힘. 소속 CASCADE가 이력 참조와 충돌할 수 있음 |
| 트리거를 잠시 끄고 삭제 | 소유자 권한이 필요하고, 그 사이 보호 규칙이 사라짐 |
| 앱 계정으로 트리거 예외 변수 사용 | 앱 취약점이 곧 기록 삭제 권한이 됨 |
| 복원본만 남기고 원본 삭제 | 삭제가 아님 |
