# 2026-11-03 가상 데이터 시연 준비 항목

갱신 2026-11-02 · 상태: **미리보기 리허설 미실시.** 같은 흐름의 자동 확인 26건은 `safeschool_test`에서 통과했습니다. 후속 조치(11단계)는 마이그레이션 승인·적용 전에는 시연하지 않습니다. 실제 학교·교직원·학생 데이터는 사용하지 않습니다.

## 1. 시연 방식 결정

| 항목 | L. 학교 PC 로컬(권장) | V. VPS Beta |
|---|---|---|
| 필요 승인 | 미리보기 DB 백업·Phase 4 마이그레이션 | VPS 작업 전체, DB·계정·Caddy·서비스, 호스트명 |
| 기존 운영 영향 | 없음 | 있을 수 있음(같은 VPS일 때) |
| 접속 범위 | 이 PC 안(`127.0.0.1`) | 외부 기기, 실제 휴대폰 |
| 미검증 위험 | 낮음 | VPS 설정 전체가 처음 실행입니다 |
| 사진 경로·Caddy 시험 | 안 됨 | 가능 |

권장 근거: 오늘 VPS 설정이 실제로 실행된 적이 없고, 시연 전날 처음 적용하면 Prototype까지 위험해집니다. 다만 L은 다른 기기 접속과 실제 휴대폰 시연이 안 됩니다. 390px 화면은 브라우저 기기 모드로 대체합니다.

## 2. 공통 준비

- [ ] 시연 방식과 시나리오 범위를 결정합니다.
- [ ] 릴리스 후보 커밋을 정합니다.
- [ ] 전체 테스트와 CI 통과를 확인합니다.
- [ ] 가상 계정 목록을 확인합니다(관리자, 교장, 안전업무 담당, 담임, 일반 교직원).
- [ ] 안내 문구에 '승인된 가상 데이터 테스트'가 표시되는지 확인합니다.
- [ ] 참석자에게 실제 정보를 입력하지 않도록 안내합니다.
- [ ] 공식 체계 비대체를 첫 화면에서 안내합니다.
- [ ] 사진은 사람·학교가 식별되지 않는 가상 사진만 사용합니다.
- [ ] 화면 캡처에 실제 정보가 없는지 확인합니다.

## 3. L 방식 준비

1. 후속 조치를 시연하려면 **별도 승인 후** `preview-migration-followup.md`대로 적용합니다. `preview-setup.cmd`와 `preview-reset.cmd`는 쓰지 않습니다.
2. `preview-start.cmd`로 실행합니다.
3. 여러 계정을 브라우저 프로필별로 준비합니다.
4. 아래 4절 시나리오를 미리 한 번 실행합니다.

## 5. V 방식을 택할 때 추가 항목(모두 별도 승인)

- [ ] VPS 메모리·스왑·디스크, Prototype 상태를 읽기 전용으로 확인합니다.
- [ ] 같은 VPS 또는 별도 VPS를 결정합니다.
- [ ] 호스트명과 DNS를 정합니다.
- [ ] `beta-roles.sql`, `pg_hba.beta.example`, 서비스, env, Caddy를 적용합니다.
- [ ] 다른 곳에서 빌드한 결과를 올립니다(서버 빌드 금지).
- [ ] 첫 마이그레이션 전후를 기록합니다(`DEPLOY_ALLOW_NEW_SCHEMA=true`는 이 명령에만).
- [ ] 가상 데이터를 넣습니다. `ALLOW_DEMO_SEED=true`는 시드 명령에만 지정합니다. 시드에는 `tsx`가 필요합니다.
- [ ] **교장·안전업무 담당 계정을 준비합니다.** `db:seed`는 이 직책 계정을 만들지 않고, `preview:setup`은 운영 모드에서 거부합니다. `operator duty-add` 방식이나 별도 절차가 필요합니다.
- [ ] 사진 업로드, Caddy 413, 오접속 거부, 백업·복원을 실제로 확인합니다.
- [ ] 시연 후 Beta 앱 중지 여부를 결정합니다.

## 6. 시연 중단 기준

실제 정보 입력, 다른 환경 데이터 노출, Prototype 이상, 계정 권한 오동작이 하나라도 발생하면 시연을 멈추고 기록한 뒤 보고합니다.

## 7. 시연에서 보여 주지 않을 것

공공 API 실제 응답(학교알리미·나이스·재난문자·기상특보, 미검증. 기본 실행에서 경보함 기상특보 카드는 '연결되어 있지 않습니다'로 표시), 실제 메일 수신(미검증), 개인정보 자동 삭제(미구현). 질문을 받으면 미검증 또는 미구현이라고 답합니다.
