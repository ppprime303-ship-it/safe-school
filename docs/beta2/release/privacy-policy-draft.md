# 개인정보 처리 설계 초안과 코드 감사

갱신 2026-11-02 · **개발 방향 초안입니다. 법적 검토·학교 승인을 거친 개인정보 처리방침이 아니며, 보존기간을 확정하지 않습니다.** 개인정보 관련 기준 문서이며, 삭제 절차 상세는 `privacy-deletion-design.md`, 학교 승인 항목은 `privacy-open-items.md`에 있습니다.

## 1. 사용자가 선택한 정책과 구현 상태

| # | 정책 | 코드 기준 상태 | 비고 |
|---|---|---|---|
| ① | 학생 최소수집 | **일치.** 학생 이름·학번·생년월일·연락처 필드 없음. 학급 단위 인원만 저장 | 소규모 학급·자유 입력에서 식별 가능성은 남음 |
| ② | 교직원 필수정보 | **일치.** `users`는 이메일, 표시 이름, 비밀번호 해시뿐. 휴대전화·생년월일·주소 필드 없음 | 소속·역할은 `school_memberships`, `member_duties` |
| ③ | 종결 후 1년 잠정 검토 | **코드에 없음(의도).** 자동 삭제·보유기간 값 없음 | 기록물 기준 확인 전 활성화 금지 |
| ④ | 전근·퇴직 | **접근 차단 일치**(아래 3절). 계정 삭제는 미구현, 미리보기만 있음 | 이력은 삭제되지 않음 |
| ⑤ | 보고서 최소화 | **대체로 일치.** 학생 이름 항목 없음, 재난대피일지는 발령·종료자 이름 제외 | 비상대피훈련일지의 역할 담당자·발령자 이름은 서식 항목으로 유지. 필요성 확인 대기 |
| ⑥ | 가상 데이터 우선 | **일치**(아래 4절) | 실제 데이터는 학교 승인 후 |

## 2. 데이터 감사

접근 범위는 코드 권한 기준이며 실제 Beta 환경에서 점검한 것은 아닙니다. 삭제는 현재 앱 기능 기준입니다.

| 항목 | 저장 위치 | 목적 | 직접 식별 | 접근 범위 | 삭제 기능 | 정책 | 수정 |
|---|---|---|---|---|---|---|---|
| 학생 식별정보 | 전용 필드 없음. 메모류 자유 입력에 유입 가능 | 해당 없음 | 입력 시 가능 | 학교 소속 교직원 | 없음 | 일치 | 안내 문구 추가 |
| 교직원 계정 | `users`, `school_memberships`, `member_duties` | 인증, 권한 | 예 | 본인, 학교 운영담당 | 없음(비활성화·회수만) | 일치 | 삭제는 결정 대기 |
| 이메일 인증·세션 | `email_verifications`, `sessions`, `user_identities` | 로그인 | 코드 HMAC, 토큰, IP | 서버만 | 만료 처리, 계정 삭제 시 CASCADE | 일치 | 없음 |
| 재난 사건·조치 이력 | `disaster_events`, `evacuation_reports`, `_revisions`, `incident_*` | 대응 기록 | 작성자 참조, 자유 기재 | 학교 소속, 권한별 | 삭제 금지 트리거 | 보존기간 미확정 | 없음 |
| 보고서·스냅숏 | `drill_logs`, `drill_log_revisions` | 공식 보고 | 훈련일지 이름 | 대피일지 권한 | 삭제 금지, 스냅숏에 이름 고정 | 일부 결정 대기 | 없음 |
| 사진·첨부 | 사진 폴더, `incident_attachments` | 현장 공유 | 사진 속 인물 | 소속 확인 후 제공 | 개별 삭제 | 위험 관리 | Beta 기본 꺼짐으로 변경 |
| 재난문자·특보 원문 | `official_alerts`, `school_alert_matches` | 경보함 | 낮음 | 학교 지역 대상, 미판정은 관리자 | 수정·삭제 금지 | 일치 | 없음 |
| 알림 확인 이력 | `alert_reads`, `staff_alerts` | 교직원별 확인 | 사용자 참조 | 본인, 학교 범위 | 계정 삭제 시 CASCADE | 일치 | 없음 |
| 소재 보고 | `staff_presences`, `_history` | 실제 재난 소재 | 예 | 권한별 | 삭제 가능, 이력 수정 금지 | 보존기간 미확정 | 없음 |
| 접속·감사 기록 | `audit_logs`, 서버 로그 | 보안 | 행위자, IP | 운영자 | 수정·삭제 금지 | 처리 결정 대기 | 없음 |
| 가입·운영자 승인 | `school_registrations`, `staff_invitations`, `platform_operators` | 학교·교직원 확인 | 예 | 운영자, 학교 운영담당 | 없음 | 일치 | 없음 |

## 3. 전근·퇴직 접근 차단

학교 자료 요청마다 DB에서 소속·학교·계정 상태를 다시 확인하므로 기존 세션으로도 다음 요청부터 차단됩니다. 결함은 없었고, 회귀 테스트(`tests/beta2-privacy-access.test.ts`)로 고정했습니다.

| 상황 | 결과 |
|---|---|
| 소속 회수, 승인 취소 | 학교 자료 거부, 계정·기록 유지 |
| 업무 회수 | 해당 권한만 다음 요청부터 사라짐 |
| 학교 이용 중지 | 거부 |
| 계정 비활성화 | 세션 무효 |
| 다른 학교 사진·보고서 경로 | 거부 |

## 4. Beta 데이터 보호

| 항목 | 상태 |
|---|---|
| 가상 모드 가입 | 메일 미설정이면 503. gmail·resend는 시작 거부. **이번에 `manual`도 시작 거부 추가** |
| 실제 학교 모드 | `BETA_SCHOOL_PILOT_APPROVED` 없이 시작 거부. 메일은 `BETA_MAIL_SENDER_APPROVED` 필요 |
| 사진 | **Beta 예시 기본 꺼짐으로 변경.** 실제 학교 모드에서 켜려면 `BETA_PHOTO_UPLOAD_APPROVED` 필요. 보고서 내려받기와 무관 |
| 외부 경보 | 학교 재난 자동 발령 없음. 모의 경보는 `is_mock`으로 분리 표시. 키는 서버 전용 |
| 표시값 한계 | 승인 표시는 승인 사실을 검증하지 못합니다 |

## 5. 삭제·폐기 기능 구분

| 구분 | 상태 |
|---|---|
| A. 전근·퇴직 접근 차단 | 구현·테스트 완료 |
| B. 개인 계정 삭제 | **미구현.** 영향 미리보기만 제공(참조 표·건수, 막히는 행, 삭제 금지 트리거) |
| C. Beta 환경 폐기 | **미실행.** 미리보기와 절차(`privacy-deletion-design.md` 3절). 가상 학교가 아닌 학교가 있으면 차단 표시 |

```powershell
npx tsx scripts/privacy-preview.ts --confirm-db <DB이름> --environment
npx tsx scripts/privacy-preview.ts --confirm-db <DB이름> --user <사용자ID>
```
읽기 전용 트랜잭션이며 건수만 출력합니다. 삭제 실행 기능과 자동 파기 일정은 없습니다.

## 6. 미확정(개발자가 정할 수 없음)

- 법정·기록물 보존기간(재난 종결 후 1년은 잠정 검토 기준)

- 비상대피훈련일지의 담당자 이름 필요성
- 개인 삭제 요청 시 보고서 스냅숏·감사 기록 처리
- 백업·로그 보유기간
- 사진 첨부 사용 여부
