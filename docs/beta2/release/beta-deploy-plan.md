# Beta 배포 차단 요인과 재난문자 서버 검증 절차

갱신 2026-11-02. **이 문서는 준비 자료입니다. 서버 접속, 키 등록, 배포를 수행했다는 뜻이 아닙니다.**

## 1. 재난문자 등록 IP

사용자 확인: 공유플랫폼에 등록된 IP는 **기존 SAFE SCHOOL 서버의 공인 IP**입니다. 학교 PC에서 호출하면 코드 32가 나오는 것이 정상입니다. 기존 등록을 지우거나 로컬 IP로 덮어쓰지 않습니다.

| 호출 위치 | 공인 IP | 예상 |
|---|---|---|
| 학교 PC | 등록 안 됨 | 코드 32. 재호출하지 않음 |
| 기존 서버 | 등록됨(송신 IP 일치는 미확인) | 정상 응답 가능 |
| Beta(같은 VPS) | 기존 서버와 같음 | 등록 추가 불필요, 호출량 공유 |
| Beta(별도 VPS) | 다름 | 추가 등록 필요. 여러 IP 허용 여부는 공개 안내에서 확인 못 함, 공유플랫폼(044-205-8461·8462) 확인 필요 |

## 2. 서버 일회성 검증(별도 승인 후)

도구: `deploy/scripts/mois-verify-once.mjs`. 의존성 없는 파일 하나이며 앱·DB·환경변수·서비스를 건드리지 않습니다.

| 항목 | 내용 |
|---|---|
| 대상 | 기존 서버의 임시 폴더(앱 폴더 밖) |
| 접근 | 사용자가 평소 SSH로 직접 실행 권장. Claude Code에 서버 접속 정보를 주지 않아도 됨 |
| 호출 | 공식 API 1회, 재시도 없음, 일일 한도 100건 중 1건 |
| 키 | 실행 중 숨김 입력. 명령행·환경변수·셸 기록·파일에 남지 않음 |
| 출력 | 코드, 구조, 필드, SN 고유 여부, 정렬, 지역 표기. 문자 본문은 길이만 |
| 영향 | Node 프로세스 몇 초. Prototype 앱·DB·설정 변경 없음 |
| 사전 조건 | `node -v`가 18 이상. 아니면 중단 |

```bash
# 1) 읽기 전용 확인: 출력 IP가 등록 IP와 같은지 눈으로 비교, 자원 여유 확인
curl -4 -s https://checkip.amazonaws.com; node -v; free -m; df -h /tmp; uptime
# 2) 학교 PC에서 복사(서버 주소는 본인이 입력)
scp deploy/scripts/mois-verify-once.mjs 계정@서버:/tmp/mois-verify-once.mjs
# 3) 서버에서 계획 확인 후 1회 실행, 파일 삭제
node /tmp/mois-verify-once.mjs --dry-run
node /tmp/mois-verify-once.mjs
rm /tmp/mois-verify-once.mjs
```

결과의 판정 줄과 항목을 전달하면 `MOIS_CBS_CONTRACT`와 대조합니다. 지역 표기가 옛 '중구'로 오는지도 이때 확인합니다. 키는 전달하지 않습니다.

`verified=true`는 이 결과가 명세와 일치하고 1쪽 정렬이 수집에 문제없을 때만 검토합니다.

## 3. 호출량 배분(키 전체 하루 100건)

DB 기반 상한은 같은 DB를 쓰는 서버끼리만 공유됩니다. 환경별 배분 합이 100을 넘지 않게 정합니다.

| 용도 | 배분 | 설정 |
|---|---|---|
| Beta 수집 | 48회(30분 간격), 상한 60 | `MOIS_CBS_INTERVAL_SEC=1800`, `MOIS_CBS_DAILY_LIMIT=60` |
| 수동 검증·장애 확인 | 최대 10회 | 집계되지 않으므로 운영 기록으로 관리 |
| 여유 | 30회 | 재시작, 예기치 않은 호출 |
| Prototype | 0 전제 | **이 키로 수집 중인지 사용자 확인 필요** |

- 코드 보호: 15분 미만 불허, 재시도 없음, 주기당 1쪽, 재시작해도 간격 안에서는 호출 안 함, 제공기관 호출 제한(코드 22·429) 뒤에는 그날 중단, Beta는 배분량 명시 필수
- 지연 정책: 최대 30분 지연입니다. 이 앱은 휴대전화 긴급재난문자를 대체하지 않는 참고 안내이므로 시범운영 기본값으로 둡니다. 학교가 더 빠른 안내를 요구하면 무단으로 늘리지 않고 이용량 증설을 문의합니다.

## 5. 배포 차단 요인과 준비 점수

점수: 0 없음, 0.25 설계·일부, 0.5 코드·설정 준비(실제 환경 미검증), 1 실제 환경 검증. 점수는 판단 기준을 밝힌 추정입니다.

| 우선 | 항목 | 점수 | 상태·필요한 것 |
|---|---|---|---|
| P0 | Beta·Prototype 분리 | 0.5 | 시작 검사·설정 완료, 미적용. 배치 결정·승인 |
| P0 | Beta 전용 DB | 0.5 | 역할 SQL·오접속 거부 테스트, DB 미생성 |
| P0 | 서버 환경변수 분리 | 0.5 | 예시·검사 완료, 주입 전 |
| P0 | HTTPS | 0.5 | Caddy 예시, 호스트명·DNS 필요 |
| P0 | 백업·독립 복원 | 0.5 | 스크립트 흐름, Beta 실측 없음 |
| P0 | 롤백 | 0.5 | 아래 6절 절차, 미시험 |
| P0 | 서버 자원 | 0 | 메모리·스왑 실측 없음 |
| P0 | 개인정보 보관·삭제 | 0.25 | 정책 초안·감사·삭제 미리보기 완료, 삭제 **미구현**. 학교 결정 후 구현(`privacy-policy-draft.md`) |
| P0 | 운영 승인·사용자 안내 | 0 | 학교장·개인정보 담당자 승인 없음 |
| P1 | 권한·학교 간 격리 | 0.5 | 권한 회수·기존 세션 차단 포함 자동 테스트 완료, 실제 환경 미점검 |
| P1 | 교직원 가입·승인 흐름 | 0.5 | Gmail 인증 E2E 로컬 성공, 운영 발신 계정 미정, 실제 교직원 승인 흐름 미실시 |
| P1 | 공공 API 호출량 | 0.5 | 코드 보호 완료, 재난문자 정상 응답 미검증 |
| P2 | 모니터링·장애 알림 | 0.25 | `health-check.sh`만, 알림 수단 미정 |

합계 5.0 / 13 = **약 38%**. 실제 환경에서 검증된 항목은 아직 없습니다.

나이스는 앱 코드가 호출하지 않으므로(`verify-neis.ts` 도구만 사용) 배포 차단 요인에서 제외합니다.

## 6. 단계별 롤백

| 단계 | 문제 발생 시 | 금지 |
|---|---|---|
| 배포 전 | Prototype 커밋·서비스 상태·건수, Caddyfile 사본 기록, Beta 백업 위치 확인 | 기록 없이 시작 |
| Beta DB 생성 후 | Beta DB만 삭제 승인 후 재생성 | Prototype DB 접근 |
| 마이그레이션 실패 | 멈추고 보고, 백업으로 별도 DB 복원 후 전환 | `migrate reset`, 스키마 DROP |
| 앱 기동 실패 | Beta 서비스만 중지, 이전 릴리스로 링크 복귀 | Prototype 서비스 재시작 |
| Caddy 오류 | 사본 복구, `caddy validate` 후 reload | 검증 없는 reload |
| 외부 API·메일 장애 | 수집만 끔(`ALERT_PROVIDERS` 제거), 메일은 `manual` 전환. 대피 보고는 독립 동작 | 키 교체로 우회 |
| 데이터 사고 | 서비스 중지, 백업 시점 복원, 담당자 보고 | 원본 덮어쓰기 |

공급자 값 `kma_warning`은 PostgreSQL에서 제거할 수 없어 이전 코드로 돌아가도 남습니다. 해당 값의 행이 있으면 이전 코드의 경보 화면을 먼저 확인합니다.

## 7. 배포 전 확인할 입력

배포 대상과 서버 IP, 메모리, 호스트명, Beta DB 계정, 백업 보관 위치, 롤백 기준 커밋, 운영 발신 메일 계정, 운영 승인자. 실제 값은 저장소에 적지 않습니다.
