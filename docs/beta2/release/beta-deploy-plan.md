# Beta 배포 차단 요인과 재난문자 서버 검증 절차

갱신 2026-11-02. **이 문서는 준비 자료입니다. 서버 접속, 키 등록, 배포를 수행했다는 뜻이 아닙니다.**

## 1. 재난문자 등록 IP

사용자 확인: 공유플랫폼에 등록된 IP는 **기존 SAFE SCHOOL 서버의 공인 IP**입니다. 학교 PC에서 호출하면 코드 32가 나오는 것이 정상입니다. 기존 등록을 지우거나 로컬 IP로 덮어쓰지 않습니다.

| 호출 위치 | 공인 IP | 예상 |
|---|---|---|
| 학교 PC | 등록 안 됨 | 코드 32. 재호출하지 않음 |
| 기존 서버 | 등록됨(송신 IP 일치는 미확인) | 정상 응답 가능 |
| Beta(같은 VPS) | 기존 서버와 같음 | 등록 추가 불필요, 호출량 공유 |
| Beta(별도 VPS) | 다름 | 추가 등록 필요. 여러 IP 허용 여부는 공개 안내에서 확인 못 함, 공유플랫폼(044-205-8461·8462) 확인 필요 |

## 2. 서버 일회성 검증(별도 승인 후)

도구: `deploy/scripts/mois-verify-once.mjs`. 의존성 없는 파일 하나이며 앱·DB·환경변수·서비스를 건드리지 않습니다.

| 항목 | 내용 |
|---|---|
| 대상 | 기존 서버의 임시 폴더(앱 폴더 밖) |
| 접근 | 사용자가 평소 SSH로 직접 실행 권장. Claude Code에 서버 접속 정보를 주지 않아도 됨 |
| 호출 | 공식 API 1회, 재시도 없음, 일일 한도 100건 중 1건 |
| 키 | 실행 중 숨김 입력. 명령행·환경변수·셸 기록·파일에 남지 않음 |
| 출력 | 코드, 구조, 필드, SN 고유 여부, 정렬, 지역 표기. 문자 본문은 길이만 |
| 영향 | Node 프로세스 몇 초. Prototype 앱·DB·설정 변경 없음 |
| 사전 조건 | `node -v`가 18 이상. 아니면 중단 |

```bash
# 1) 읽기 전용 확인: 출력 IP가 등록 IP와 같은지 눈으로 비교
curl -4 -s https://checkip.amazonaws.com; node -v
# 2) 학교 PC에서 복사(서버 주소는 본인이 입력)
scp deploy/scripts/mois-verify-once.mjs 계정@서버:/tmp/mois-verify-once.mjs
# 3) 서버에서 계획 확인 후 1회 실행, 파일 삭제
node /tmp/mois-verify-once.mjs --dry-run
node /tmp/mois-verify-once.mjs
rm /tmp/mois-verify-once.mjs
```

결과의 판정 줄과 항목을 전달하면 `MOIS_CBS_CONTRACT`와 대조합니다. 지역 표기가 옛 '중구'로 오는지도 이때 확인합니다. 키는 전달하지 않습니다.

`verified=true`는 이 결과가 명세와 일치하고 1쪽 정렬이 수집에 문제없을 때만 검토합니다.

## 3. 호출량 배분(키 전체 하루 100건)

DB 기반 상한은 같은 DB를 쓰는 서버끼리만 공유됩니다. 환경별 배분 합이 100을 넘지 않게 정합니다.

| 용도 | 배분 | 설정 |
|---|---|---|
| Beta 수집 | 48회(30분 간격), 상한 60 | `MOIS_CBS_INTERVAL_SEC=1800`, `MOIS_CBS_DAILY_LIMIT=60` |
| 수동 검증·장애 확인 | 최대 10회 | 집계되지 않으므로 운영 기록으로 관리 |
| 여유 | 30회 | 재시작, 예기치 않은 호출 |
| Prototype | 0 전제 | **이 키로 수집 중인지 사용자 확인 필요** |

- 코드 보호: 15분 미만 불허, 재시도 없음, 주기당 1쪽, 재시작해도 간격 안에서는 호출 안 함, 제공기관 호출 제한(코드 22·429) 뒤에는 그날 중단, Beta는 배분량 명시 필수
- 지연 정책: 최대 30분 지연입니다. 이 앱은 휴대전화 긴급재난문자를 대체하지 않는 참고 안내이므로 시범운영 기본값으로 둡니다. 학교가 더 빠른 안내를 요구하면 무단으로 늘리지 않고 이용량 증설을 문의합니다.

## 4. 배포 차단 요인

| 항목 | 상태 | 필요한 것 |
|---|---|---|
| Beta 서버·DB 분리 | 코드·설정 준비, **미적용** | 배치 결정(같은 VPS 또는 별도), 승인 |
| HTTPS | Caddy 예시만 | 호스트명, DNS |
| 공공 API 출발 IP | 재난문자 위 1절 | 배치 결정 후 확인 |
| 수집 주기·쿼터 | 코드 완료, 재난문자 정상 응답 미검증 | 2절 실행 |
| Gmail | 실발송 미검증, 운영 계정 없음 | 시험 실행, 운영 발신 계정 결정 |
| 백업·복원 | 스크립트 흐름만, Beta 실측 없음 | 환경 구축 후 `backup-restore.md` |
| 개인정보 보관·삭제 | 설계안만, **미구현** | 학교 결정, 구현 |
| 권한·학교 간 격리 | 자동 테스트 완료 | 실제 환경 점검 |
| 모니터링·복구 | `health-check.sh`만, 경보 없음 | 알림 방법 결정 |
| 롤백 | 절차 문서만, **미시험** | 환경 구축 후 시험 |
| 학교 운영 승인 | **없음** | 학교장·개인정보 담당자 |

## 5. 배포 전 확인할 입력

배포 대상과 서버 IP, 메모리, 호스트명, Beta DB 계정, 백업 보관 위치, 롤백 기준 커밋, 운영 승인자. 실제 값은 저장소에 적지 않습니다.
