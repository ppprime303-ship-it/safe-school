## 1. 삭제 기능의 현재 상태

**자동 삭제·익명화 도구가 없습니다. 현재 12월 31일 삭제를 시스템이 보장하지 않습니다.**

| 항목 | 상태 |
|---|---|
| 가입 화면 안내 | "2026년 12월 31일 삭제 예정"을 표시합니다(사용자 결정, 변경 없음) |
| 자동 삭제 | 없음 |
| 수동 삭제 절차 | 정의되지 않았습니다 |
| 계정 탈퇴 | 기능 없음 |
| 사진 삭제 | 대응 담당자가 개별 삭제합니다. 파일은 제거되고 DB 행은 삭제 표시로 남습니다. 백업에는 남습니다 |
| 감사 기록 | DB 트리거가 수정·삭제를 막습니다. 삭제하려면 승인된 정비 절차가 필요합니다 |
| 소재 이력·제보 이력 | 트리거 제약이 있어 일괄 삭제 절차를 설계해야 합니다 |

| 메일 서비스 발송 기록 | 사용할 경우 업체의 보관 기간을 확인해야 합니다 |

**필요 조치:** 실제 학교 사용자가 가입하기 전까지 12월 31일 안내를 실행할 수 있는 절차를 확정하거나, 안내 문구를 다시 결정해야 합니다.

## 2. 삭제 절차 초안(미구현·미실행)

1. 대상 범위와 기준일을 정하고 승인받습니다.
2. 백업하고 복구 가능 여부를 확인합니다.
3. 대상 건수만 보고합니다(이름·이메일 제외).
4. 가상 DB에서 먼저 시험합니다.
5. 승인 후 실행합니다.
6. 결과를 건수로 대조합니다. DB, 사진 파일, 백업, 서버 밖 사본, 로그를 포함합니다.
7. 학교에 결과를 알리고 기록합니다.

**이 절차를 완료하기 전에는 삭제가 끝났다고 표현하지 않습니다.**

## 4. 실제 학교 사용자 가입 전 필요한 승인

`BETA_DATA_MODE=school_pilot`과 `BETA_SCHOOL_PILOT_APPROVED=true`는 아래 항목을 모두 충족한 뒤에만 설정합니다. **이 설정은 승인 사실을 검증하지 못합니다. 운영자의 확인 표시일 뿐입니다.**

- [ ] 학교장 또는 교감이 목적, 기간, 범위, 중단 방법을 듣고 동의했습니다(가능하면 내부 결재·공문).
- [ ] 학교 개인정보 담당자가 수집 항목, 보관 위치, 메일 서비스를 검토했습니다.
- [ ] 위 3절의 항목을 확정하고 문서화했습니다.
- [ ] 참여자에게 수집 항목, 목적, 보관 기간, 삭제 방법, 문의처를 고지하고 동의 기록을 남겼습니다.
- [ ] 교직원 소재 수집 범위를 고지했습니다(실제 재난에서만, 열람 범위, 보관 기간).
- [ ] 참여는 자발적이고 탈퇴·삭제 요청이 가능함을 안내했습니다.
- [ ] 공식 재난 대응 체계, 119 신고, 비상연락망을 대체하지 않음을 안내했습니다.
- [ ] 학교 등록 승인 방법(공문·대표전화 확인 등)을 정했습니다.
- [ ] 유출 의심 시 연락 순서를 확정했습니다.
- [ ] 삭제 절차를 확정했습니다(1·2절).
- [ ] 접근 권한자 명단을 기록했습니다(서버, 설정 파일, DB, 백업).
- [ ] 메일 방식을 결정하고 실제 수신을 확인했습니다.
