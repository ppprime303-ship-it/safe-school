# Beta PILOT 2 — 개인정보 처리·보관·삭제 정책안(검토용 초안)

작성 2026-10-30 · 상태: **정책안(미확정)** — 학교장·학교 개인정보 담당자 협의와 운영 책임자 승인 전에는 운영에 적용하지 않습니다.
법정 보관 기간이나 학교·교육청의 공식 기준은 확인하지 못했습니다. 아래 기간은 **비교용 대안**이며 추정으로 확정하지 않습니다.
자동 삭제 작업은 만들지도, 실행하지도 않았습니다.

## 0. 핵심 원칙
- **모의훈련에서는 교직원 소재정보를 수집하지 않습니다.** 훈련은 안내 알림과 확인 기록만 남깁니다(서버 403·DB 트리거로 강제).
- 교직원 소재는 **실제 재난**에서만, 본인이 직접, 최소한으로(교내/교외·교내 장소·대피 지원 여부) 받습니다. GPS·교외 주소·자유 메모는 받지 않습니다.
- 알림 '확인'은 안전·위치 확인이 아닙니다.

## 2. 처리 목적
1. 학교 재난 대응 시 교직원 확인(실명) 및 학교 소속·권한 관리
2. 학생 대피 현황 파악(학급 보고)
3. **실제 재난** 시 교내 교직원 수·위치·대피 지원 가능 인원 파악(소재)
4. 발령 사실 안내와 확인 여부 파악(알림) — 실제·훈련
5. 권한 변경·정정의 책임 추적(감사)

## 4. 실제 재난과 모의훈련의 보관 필요성 차이
| 구분 | 실제 재난 | 모의훈련 |
| --- | --- | --- |
| 교직원 소재 | 사후 점검·보고·분쟁 대응 근거로 일정 기간 필요할 수 있음 | **수집하지 않음** |
| 알림 확인 | 대응 경과 확인 근거 | 훈련 참여 확인 정도(개인 평가 목적 사용 금지 권고) |

## 5. 알림 확인 기록 보관 기준(대안)
| 대안 | 내용 | 장점 | 단점 |
| --- | --- | --- | --- |
| A1 | 사건 종료 후 **30일** 삭제 | 최소 보관 | 사후 점검 시 근거 부족 가능 |
| A2 | 사건 종료 후 **1년**(학년도 말까지) 보관 후 삭제 | 연간 훈련·점검 주기와 맞음 | 보관 부담 |
| A3 | 기간 후 **익명화**(대상 수·확인 수만 남기고 개인 행 삭제) | 통계 유지 + 개인 정보 제거 | 익명화 도구 개발 필요 |
- 권고 검토 방향: 훈련 알림은 짧게(A1), 실제 재난 알림은 소재와 같은 기준.

## 6. 소재 응답·변경 이력 보관 기준(대안, 실제 재난만)
| 대안 | 내용 | 장점 | 단점 |
| --- | --- | --- | --- |
| B1 | 사건 종료 후 **7일** 삭제 | 민감 위치정보 최소 보관 | 사후 점검·보고 작성 기간 부족 가능 |
| B2 | 사건 종료 후 **30일** 삭제(이력 포함) | 사후 보고 작성 기간 확보 | 그 사이 열람 통제 필요 |
| B3 | 종료 후 30일 뒤 **익명 집계만 남기고** 개인 행·이력 삭제 | Phase 4 보고서(익명 집계)와 일치 | 삭제 도구 필요 |
| B4 | 학교 공식 기록물 기준에 따름 | 기관 기준 정합 | 기준 확인 필요(미확인) |
- Phase 4 보고서에는 익명 집계만 들어가므로(이름·위치·명단 금지), 보고서 보관 기간이 개인 소재 보관 기간을 늘리지 않습니다.

## 7. 감사 기록과 삭제·익명화의 충돌
- `audit_logs` 는 DB 트리거로 수정·삭제가 금지되어 있습니다(책임 추적).
- 감사 기록에 남는 개인 정보: 행위자 계정 ID, IP, 일부 변경 전후 값(예: **정정 전 성명**, 이양 전후 역할). 소재 위치 내용은 기록하지 않도록 이미 설계했습니다.
- 선택지
  1. 감사 기록은 별도(더 긴) 보관 기간을 두고 그 기간이 지나면 **승인된 정비 절차**로 트리거를 잠시 해제해 일괄 삭제(절차·승인 기록 필요)
  2. 앞으로 감사 기록에는 개인 값 대신 **가명 ID·해시**만 남기도록 변경(정정 전 성명 등)
  3. IP는 일정 기간 후 마스킹
- 어느 쪽이든 운영 DB 변경이므로 별도 승인 대상입니다.

## 8. 소속 회수·계정 탈퇴
| 상황 | 현재 동작 | 제안 |
| --- | --- | --- |
| 소속 회수 | 세션 삭제, 담당 학급·직책·대리 지정 종료, 소재·알림·보고 행은 보존(집계에서만 제외) | 보관 기간 정책에 따라 사건 단위로 정리 |
| 계정 탈퇴 | **기능 없음**(운영자 처리) | 탈퇴 시 실명 → '탈퇴한 교직원' 등 가명 처리, 보고·이력은 계정 ID로 유지(행위 근거) — 설계 필요 |
| 성명 정정 | 학교 관리자만, 비밀번호 재확인, 감사 기록(정정 전 성명 포함) | 7번 선택지와 함께 결정 |

## 9. 재난 종료 후 접근 제한(현재 구현)
- 소재 신규·수정 불가(서버 409 + DB 트리거), 알림·응답·이력 보존.
- 일반 교직원: 본인 응답과 숫자 요약만. 상세 권한자: 개인별·이력 조회 가능.
- 제안: 보관 기간 중이라도 종료 후 일정 기간(예: 30일)이 지나면 개인별 상세 조회를 막고 요약만 남기는 단계적 제한.

## 10. 보관 기간 만료 시 삭제·익명화 절차(제안, 미구현)
1. 대상 선정: 종료 시각 + 기간이 지난 **실제 재난** 사건(훈련은 소재 없음, 알림만)
2. 사전 백업 확인 → 대상 건수 보고 → 승인
3. 사건 단위 트랜잭션: 익명 집계 저장(필요 시) → `staff_presence_history` → `staff_presences` → `staff_alerts` 순 삭제
4. 삭제 결과(사건 ID·건수·시각·승인자)를 별도 기록(개인 정보 없이)
5. 백업 보관본도 같은 기준으로 만료(기존 운영 문서: 백업 14일)
- 도구는 승인 후 개발, 테스트 DB에서 먼저 검증. **지금은 실행·배포하지 않음.**

## 11. 학교 개인정보 담당자와 협의할 결정사항
1. 실명 수집 목적·보관 기간(현 가입 안내 문구와의 충돌 해소)
2. 실제 재난 소재 보관 기간(B1~B4 중) 및 익명화 여부
3. 알림 확인 기록 보관 기간(실제·훈련 각각)
4. 감사 기록 보관 기간과 개인 값 처리(7번)
5. 상세 열람 범위(현재: 관리자·교장·교감·안전업무 담당) 유지 여부
6. 탈퇴·전보 시 처리 방식
7. 고지 방식(가입 화면, 시범운영 안내문, 학교 내 공지)과 동의 기록 보관
8. 국외 메일 서비스 사용 여부(Gmail 등)와 고지
