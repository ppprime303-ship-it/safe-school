# STEP 3-D 재난 대응 보고서·훈련일지 자동작성 — 1차 설계(서식 분석·시제품)

작성 2026-10-22 · 브랜치 `step-3d-design`(기준 `step-3c-ui` `8257b62`) · 상태: **사용자 검토 대기, 앱 코드·DB·마이그레이션 변경 없음**

> 이 문서는 1차 작업(서식 분석·시제품)의 결과입니다. 사용자가 시제품을 확인하고 승인하기 전에는 앱 기능을 만들지 않습니다.

## 1. 첨부 문서 분석 방법과 범위
- 첨부 HWP 4개(HWP5 형식)를 이 작업공간에서 직접 읽었습니다. 외부 변환 도구 설치가 막혀 있어 공개된 HWP5 구조(OLE 복합 파일 + 압축 레코드)를 표준 라이브러리로 해석하는 도구를 만들어 **본문 글자·표 칸 구분·첫 쪽 미리보기 그림**을 추출했습니다.
- 읽은 것: 본문 텍스트, 표/칸 경계, 문서 안 그림 개수, 첫 쪽 미리보기 이미지(훈련일지는 첫 쪽이 문서 전체).
- 읽지 못한 것: 칸 너비·병합 정보·글꼴·쪽 여백의 정확한 값(미리보기 그림으로 모양만 확인). 대피도 등 그림 안의 글자.
- 개인정보 처리: 원본 학교명·교직원 실명·전화번호·주소·사진은 이 저장소의 어떤 파일에도 옮기지 않았습니다. 원본 HWP도 커밋하지 않았습니다.
- 이 문서들은 한 학교(병설유치원 포함)의 실제 사례이며, 모든 학교 공통 법정 서식으로 가정하지 않았습니다.

## 2. 서식별 구성 분석

### A. 비상대피훈련일지(지진) — 우선 개발 대상 · 원본 1쪽
원본에서 **확인한** 구성(위에서 아래 순서):

| 순서 | 항목 | 원본의 형태 | 원본 기재 예(내용 일반화) |
| --- | --- | --- | --- |
| 1 | 제목 | `비상대피훈련일지(지진)` 가운데 큰 글씨 | 재난 유형이 괄호로 들어감 |
| 2 | 기관명 | 오른쪽 정렬 | 학교(유치원) 이름 |
| 3 | 일시 | 한 줄 | `2026. 9. 9.(수) 10:20 ~ 11:20 (총 60분)` |
| 4 | 참가인원 | 두 칸 | `교직원 ○명 / 유아 ○명` + `총 ○명` |
| 5 | 역할담당 | 세로 병합 + `구분/담당자` 6행 | 안전교육 및 대피 / 신고 / 안내 방송 / 부상 치료 / 실내 확인 / 소요시간 측정·최종인원 점검 — 담당자는 **직책 이름**(각 반 담임, 원감 등) |
| 6 | 훈련 내용 | 가로 띠 제목 | — |
| 7 | (재난)발생시 대피(집결)장소 | 문장 | `각 반 대피로를 따라 운동장으로 대피` |
| 8 | 대피소요 시간 | 측정값 | `○분 ○○초` |
| 9 | 평가 | 세로 병합 + `평가내용 / 평가결과(O, X) / 비고` 6행 | 신속성, 경로 효율성, 장소 안전성, 교사 역할 수행, 비상벨·사이렌 적절성, 유아 반응 |
| 10 | 추후 대피훈련 시 반영사항 | 서술 | 사전교육 방식, 관찰 내용, 시설 점검 필요 사항 |
| 11 | 사진 | 사진 3장 가로 배치 | 활동 사진 |

관찰: 원본에는 평가결과가 O인데 비고에 '안내방송이 나오지 않음', '들리지 않음'처럼 개선이 필요한 내용이 적힌 행이 있습니다. 평가 판단은 교직원 몫이므로 앱이 바꾸지 않되, **O/X와 비고를 한 줄에 함께 보이게** 해 검토할 때 눈에 띄도록 설계합니다(앱이 판정하지 않음).

### B. 황사·미세먼지 대응 교육 및 훈련일지 — 확장 서식 · 원본 1쪽
- A와 같은 표 틀(실시일·참가인원·역할담당·훈련내용·평가 O/X·비고·사진).
- 다른 점: 실시일이 **기간**(`4. 20.(월) ~ 4. 24.(금)`), 훈련 내용이 **대상별(유아/교직원)**, 평가 항목이 교육 중심 3개(내용 적절성, 교직원 참여, 유아 참여). **대피장소·대피소요시간·추후 반영사항 칸이 없음.**
- 설계: 서식을 '공통 틀 + 유형별 구성'으로 만듭니다(아래 5절). 대피 이벤트가 없는 교육 활동이라 STEP 3-A 기록과 연결되지 않으며, 대부분 직접 입력입니다.

### C. 재난대응훈련 실시 계획서 — 후속 개발 대상
| 항목 | 9월 유치원 지진·해일 계획 | 5월 학교 통합훈련(지진·화재·민방공) 계획 |
| --- | --- | --- |
| 목적·개요 | 목적 3항 | 목적, 훈련 개요(일시·대상·장소·연기 조건) |
| 일시·장소 | 교육일시 | 일시(교시), 장소(교실·운동장), 우천·미세먼지 시 익일 연기 |
| 대상·내용 | 활동명·목표·자료(동영상)·방법·비고 표 | 시간대별 훈련표(시간·주요훈련·내용·상영시간) |
| 시나리오 | 붙임: 구분·행동요령·방송 멘트 | 시각별 방송 멘트 표(안내→지진→화재→상황 종료) |
| 역할·업무분장 | 직책·인원·임무 | 붙임: 훈련대책반 조직(지휘·대피유도·응급구조·소화진압), 조직별 역할·준비물 |
| 대피 동선·장소 | 층별 대피도(그림), 대피장소, 우천 시 대체 장소 | 대피로 안내, 운동장 학급 배치도 |
| 붙임 | 시나리오 | 가정통신문, 국민행동요령 자료, 대피소 찾기 과제 |

계획서는 그림(대피도)·학교별 조직·방송 원고가 많아 자동작성 효과가 작고 검토 부담이 큽니다 → **후속 고도화로 분리**합니다. 단, 계획서의 '일시·장소·대피장소·역할'은 나중에 훈련일지의 기본값으로 재사용할 수 있습니다(`disaster_events.drill_plan_id` 열이 STEP 1부터 예약되어 있음 — 'STEP 5에서 훈련계획과 연결').

## 3. STEP 3-D 권장 자동작성 서식 — 비상대피훈련일지
- 원본 A의 순서·칸을 그대로 따르고, 다음 두 가지만 **제안(사용자 결정)** 합니다.
  1. `학급별 대피 보고` 행 추가(원본에 없음): 학급·재적·대피 확인·사전 파악 부재·미확인·부상, 미보고 학급은 '미보고'.
  2. 유치원 문서의 '유아'를 학교급에 맞게 '학생/유아'로 바꿔 씀.
- 시제품: `prototypes/step3d/evacuation-drill-log.html`(화면), `evacuation-drill-log.pdf`(인쇄 모양), `비상대피훈련일지_HWPX시험본.hwpx`(한글 열기 시험용).

| --- | --- | --- | --- |

## 5. 생성·검토 흐름(2차 개발 제안)
1. 관리자가 상황판에서 '종료'한 훈련(또는 종료 목록)에서 **'훈련일지 만들기'** → 서버가 ①② 값을 모아 **초안**을 만듦(이벤트당 1건, 다시 누르면 기존 초안 열기).
2. 편집 화면: STEP 3-C 안내문 편집과 같은 방식(작성 중/작성 완료 + '저장하기' 한 단추, 판 번호·수정 이력·409 충돌).
3. 자동값은 '시스템 기록 기준'으로 표시하고, 교직원이 고친 값은 그대로 존중(다시 불러오기 단추는 덮어쓰기 확인).
4. 미리보기 → **내려받기(HWPX 우선, PDF 보조)** → 한글에서 마무리 → K-에듀파인 결재 문서에 **사용자가 직접 첨부**.
5. '작성 완료'는 앱 안의 문서 상태이며 결재·보고 완료가 아님을 화면에 표시.

유형 확장: `서식 정의 = 공통 틀(제목·기관·일시·참가·역할·평가·사진) + 유형별 구성(대피장소/소요시간 칸 사용 여부, 평가 항목 목록, 훈련 내용 칸 구조)`. 지진 대피(A)와 황사·미세먼지 교육(B)을 같은 틀로 다룰 수 있게 합니다. 서식 정의는 코드 데이터로 두고(예시문 21개와 같은 방식), 학교가 평가 항목·역할 구분을 고친 값만 저장합니다.

## 6. 출력 형식과 기술적 제약
| 형식 | 가능성 | 확인된 것 | 확인 안 된 것 |
| --- | --- | --- | --- |
| HTML 미리보기·인쇄 | 가능 | 시제품을 Chromium으로 A4 1쪽 PDF 출력 확인 | — |
| PDF | 가능(브라우저 인쇄 또는 서버 생성) | 위와 같음. 결재 첨부용 '보기 전용'에 적합 | 서버에서 PDF를 만들려면 Replit에 브라우저 엔진 필요 — 미검증 |
| **HWPX** | 직접 생성 가능성 있음 | HWPX는 공개 XML 묶음(ZIP). 한글 없이 만든 시험본의 ZIP·XML 구조 검사 통과 | **한글에서 열리는지·표가 깨지지 않는지·편집되는지 미확인**(사용자 확인 필요). 시험 생성기는 가로 병합만 지원(세로 병합 미구현) |
| HWPX(서식 채우기) | 대안 | 학교 원본 서식을 한글에서 HWPX로 저장 → 앱은 칸의 글자만 바꿔 넣기 | 원본 서식을 HWPX로 받아야 시험 가능. 표 구조를 그대로 유지할 가능성이 가장 높음 |
| HWP(5.0) | 어려움 | 읽기는 가능(이번 분석) | 쓰기는 바이너리 형식이라 이번 범위에서 제외 |
| DOCX | 보조 | 한글에서 열 수 있으나 표 모양이 바뀔 수 있음 | 미검증 |

권장 순서: ① HTML 미리보기 + PDF → ② HWPX 시험본 한글 확인 → ③ 확인되면 학교 서식 HWPX에 값 채우기 방식으로 확정. **검증 전에는 '한글 호환'이라고 안내하지 않습니다.**

## 7. 추후 개발 범위
- 2차(승인 후): 비상대피훈련일지 초안 생성·편집·이력·HTML/PDF·HWPX 시험 출력, 서식 정의 구조, 황사·미세먼지 일지(B)
- 3차 이후: 계획서(C) 작성 지원, 계획서 → 일지 기본값 연결(`drill_plan_id`), 역할 담당·교직원 참가 기록, 사진 저장
- 범위 밖: K-에듀파인 자동 업로드·결재 상신, AI의 평가·반영사항 작성
