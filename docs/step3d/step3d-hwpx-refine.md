## 3. PDF 시제품과 같지 않은 부분(구조상·의도)
- 화면 전용 요소 없음: 색 구분(파랑·청록·주황), 안내 문구, 오른쪽 참고 패널, 입력칸 테두리 — 인쇄용 PDF에서도 사라지는 요소라 HWPX에는 넣지 않음.
- O/X: PDF는 선택 단추, HWPX는 글자 `□ O    □ X`(한글에서 □를 ■로 바꾸거나 O/X만 남기는 방식). 한글 '양식 개체(라디오 단추)'는 호환 위험이 있어 쓰지 않음.
- 학급별 대피 보고: PDF는 표 안의 작은 표, HWPX는 **같은 표의 칸**으로 구성(표 안에 표를 넣지 않아 한글에서 덜 흐트러짐).
- 글자 폭: 비교용 PDF는 이 작업공간에 맑은 고딕이 없어 대체 글꼴(Noto Sans CJK)로 그렸음 → 한글(맑은 고딕)에서 줄바꿈 위치가 조금 다를 수 있음.
- 행 높이: 한글은 칸 안 글자가 넘치면 행을 늘림. 계산상 본문 표 높이 244.9mm + 제목·학교명 약 21mm = 약 266mm(쓸 수 있는 높이 273mm)로 여유 7mm. 글자를 많이 쓰거나 사진을 크게 넣으면 2쪽으로 넘어갈 수 있음.

## 5. 재사용 구조(앱 연결은 승인 후)
```
tools/hwpx/
  drill_log_layout.py   데이터(JSON) → 배치 정의(행 높이·셀·병합·문구), 데이터 정책, 배치 검사
  hwpx_writer.py        배치 정의 → HWPX(base_template.hwpx 기반) / HTML(비교용)
  build_drill_log.py    명령줄 실행(HWPX + 비교 PDF)
  sample_drill_data.json  가상 시연 데이터(앱 서버가 만들 데이터 모양)
  test_drill_log.py     구조·정책 검사 12건
  base_template.hwpx    대회 공고문 HWPX의 패키지·글꼴·스타일 목록(본문은 매번 새로 씀)
```
- 앱에서는 서버가 `sample_drill_data.json`과 같은 모양의 데이터를 만들고, 같은 배치 규칙으로 HWPX를 내려주는 방식(TypeScript로 옮기거나 Python 실행)을 2차 개발 때 결정합니다.
- 황사·미세먼지 일지 등 다른 유형은 `build_layout`과 같은 함수를 하나 더 만들면 됩니다(쓰는 `hwpx_writer`는 공통).
