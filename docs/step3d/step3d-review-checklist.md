# STEP 3-D 시제품 사용자 검토 체크리스트

시제품: `prototypes/step3d/evacuation-drill-log.html`(브라우저에서 열기), `evacuation-drill-log.pdf`(인쇄 모양), `비상대피훈련일지_HWPX시험본.hwpx`(한글에서 열기)

## 1. 형태
- [ ] 학교에서 쓰는 비상대피훈련일지와 모양·순서가 비슷한가
- [ ] A4 1쪽에 들어가는 분량이 적당한가(PDF로 확인)
- [ ] 제목의 재난 유형 표시(괄호)와 기관명 위치가 맞는가

## 2. 항목
- [ ] 빠진 항목이 없는가(일시·참가인원·역할담당·대피장소·소요시간·평가·반영사항·사진)
- [ ] '학급별 대피 보고' 행(원본에 없음)을 **넣을지 / 뺄지 / 붙임으로 돌릴지**
- [ ] 역할 구분 6개 기본값이 학교 실정과 맞는가(추가·삭제할 역할)
- [ ] 평가 항목 6개가 맞는가('유아의 반응' → '학생의 반응'으로 바꿈)
- [ ] 평가 결과를 O/X 두 가지로 둘지, '△(보완 필요)' 같은 선택지가 필요한지

## 3. 자동 입력
- [ ] 일시를 '발령~종료 시각'으로 채우는 것이 맞는가(실제 훈련 시간과 다를 때 고치기)
- [ ] 학생 수를 '보고된 학급의 대피 확인 합계'로 쓰고 미보고 학급을 따로 표시하는 방식이 맞는가
- [ ] 대피 장소를 발령 때 입력한 값으로 채우는 것이 맞는가
- [ ] 대피 소요 시간을 자동 계산하지 않고 '참고값'만 보여 주는 방식에 동의하는가

## 4. 직접 수정할 부분
- [ ] 주황색(교직원 확인) 칸이 한눈에 구분되는가
- [ ] '색 표시 끄고 문서 모양 보기'와 인쇄 결과에서 표시가 깔끔하게 사라지는가
- [ ] 오른쪽 '시스템 기록 참고'가 반영사항 작성에 도움이 되는가

## 5. 한글·K-에듀파인
- [ ] HWPX 시험본이 한글에서 열리는가
- [ ] 표가 깨지지 않고, 칸 안 글자를 고칠 수 있는가
- [ ] 세로 병합이 없는 시험본 모양으로도 쓸 만한가, 아니면 원본 서식(HWPX로 저장한 파일)에 값을 채우는 방식이 필요한가
- [ ] 결재 첨부는 HWPX와 PDF 중 무엇을 주로 쓰는가

## 6. 결정 요청
- [ ] 2차 개발(앱 구현) 착수 승인
- [ ] 원본 일지 서식을 **개인정보를 지운 HWPX**로 저장해 제공 가능 여부(서식 채우기 방식 시험용)
- [ ] 사진을 앱에 저장할지(저장 시 얼굴 노출·보관 기간 정책 필요)
