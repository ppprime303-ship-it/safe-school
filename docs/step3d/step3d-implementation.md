## 1. 구현 범위와 보류 범위

### 구현함(기존 보안 수준을 낮추지 않는 추가형)
| 영역 | 내용 |
| --- | --- |
| 권한 계층 | 기본 역할(admin/homeroom/staff)은 그대로 두고, 직책·업무(`member_duties`)를 별도 행으로 겸임 표현 → 권한을 **합산**(`shared/permissions.ts`, 화면·서버 같은 함수) |
| 직책 | 교장(학교당 1명)·교감(최대 2명): **플랫폼 운영자 도구로만** 등록(확인 방법 필수, 직무대리 표시 가능). 앱에서는 지정·종료 불가 |
| 업무 | 안전업무 담당·앱 운영담당: 여러 명, 겸임 가능. 앱 운영담당(또는 기존 관리자)이 지정·해제(비밀번호 재확인), **자기 자신에게 지정 불가** |
| 발령·종료 | 기존 관리자 + 교장·교감 + 안전업무 담당. 발령자·종료자가 달라도 됨(기록·감사 유지). 실제 상황 확인 절차·중복 발령 방지는 기존 그대로 |
| 가입 승인·배정 | 기존 관리자 + 앱 운영담당. 앱 운영담당은 학교 관리자 계정과 교장·교감 계정을 회수할 수 없음 |
| 마지막 운영자 보호 | 교직원 승인 권한자(관리자+앱 운영담당)가 0명이 되는 해제·회수 거부 |
| 기록 보존 | 직책·업무는 삭제 불가, 종료(사유·종료자·시각)만. 회수 시 업무도 함께 종료(기록 유지) |
| 훈련일지 | 종료된 **모의훈련**에만 이벤트당 1건, 자동작성(스냅숏)·담당자 입력·판 번호·수정 이력(DB 트리거)·동시 수정 409·원본 변경 알림과 '다시 불러오기' |
| 출력 | **HWPX(붙임형)** 서버 생성(TypeScript, 새 의존성 없음), 미리보기(같은 배치 함수), PDF는 브라우저 인쇄(보조) |

### 보류 — 사용자 결정 필요(구현하지 않았거나 안전한 쪽으로 제한함)
1. **교장·교감 직책의 기관 확인 방식**: 지금은 플랫폼 운영자가 공문 등으로 확인한 뒤 `npm run operator -- duty-add`로 등록하는 방식만 있음(앱 화면에서 신청·확인 흐름 없음). 학교 등록 때의 관리자 자격 확인과 같은 수준. 화면 신청 흐름·교육청 연동은 추가 승인 필요.
2. **기존 `admin` 역할 분리**: 기존 관리자는 지금까지의 기능(발령·종료·상황판·승인·학급·소재지)을 그대로 쓰고, 새로 '업무 담당자 지정'과 '훈련일지 열람'만 더했음. **훈련일지 작성·수정은 자동으로 주지 않음**(안전업무 담당 지정 필요 — 단, 자기 자신에게는 지정할 수 없어 다른 운영 권한자 또는 플랫폼 운영자가 지정). 관리자를 교장·교감·운영담당으로 나누는 재배정은 하지 않음.
3. **최초 운영담당 지정**: 플랫폼 운영자 도구(`duty-add … app_operator`)로 가능. 학교 등록 승인 때 자동 지정은 하지 않음.
4. **앱 운영담당이 다른 사람에게 '앱 운영담당'·'안전업무 담당'을 지정**할 수 있음(지시서의 '업무 권한 배정'). 안전업무 담당은 발령 권한이 있으므로, 운영담당 지정을 관리자·플랫폼 운영자로 더 좁힐지 결정 필요.
5. 활동 사진 저장(앱 저장 안 함 — 내려받은 한글 파일에 직접 삽입), 계획서 자동작성, 황사·미세먼지 일지는 다음 단계.

## 5. DB 마이그레이션 `20261023000000_duties_drill_logs`(추가형)
- 새 열거형 3개, 새 테이블 3개(`member_duties`, `drill_logs`, `drill_log_revisions`), 함수·트리거. 기존 테이블 변경·DROP·ALTER TABLE 없음.
- `member_duties`: 교장 부분 UNIQUE(학교당 활성 1), 교감 최대 2명(트리거), 같은 사람·같은 업무 활성 1건, 교장·교감은 플랫폼 운영자+확인 방법 필수(CHECK), 승인된 같은 학교 교직원만, 종료만 허용(삭제·되살리기·변경 불가).
- `drill_logs`: 이벤트당 1건(UNIQUE), 같은 학교·종료된·모의훈련 이벤트만(트리거), 작성 중·판 1로 시작, 판 정확히 +1, 학교·이벤트·서식·작성자 변경 불가, 삭제 불가, JSON은 객체만. 수정 이력은 DB 트리거가 기록(앱이 직접 쓰지 않음).
- 안전성 점검(작업공간 임시 PostgreSQL, 마이그레이션 5개 처음부터 적용): **STEP 3-D 44/44, STEP 3-C 55/55(회귀)** — `tools/db-checks/check_step3d_migration.py`

## 6. HWPX·PDF
- 서버(TypeScript)가 HWPX를 만듦: `server/src/drilllog/hwpx.ts`(배치 → XML), `zip.ts`(ZIP, mimetype 첫 항목 무압축, CRC). 양식 자산 `server/assets/hwpx-base/`(공고문 본문·작성자 정보 제거본). **Python 실행 불필요**(Replit에 Python 의존성 추가 없음). 자산 경로는 `process.cwd()` 기준이라 저장소 맨 위에서 서버를 실행해야 함(현재 `npm run dev`/`npm start` 방식과 같음).
- 배치는 사용자가 한글에서 확인한 Python 시험본(`tools/hwpx`)과 같은 규칙을 `shared/drillLog.ts`로 옮김. TS 생성본과 Python 생성본의 파일 목록·XML 태그·속성 구성이 같음을 비교(작업공간). 붙임은 학급 32개마다 쪽이 늘어남, 마지막 쪽에만 합계.
- 사용자 입력은 XML 이스케이프·제어문자 제거 후 삽입. 쉘 명령 실행 없음.
- 생성 실패 시 500 `doc_generation_failed`(입력 내용은 저장된 상태, 로그에 원인).
- PDF: 미리보기 화면의 '인쇄 / PDF로 저장'(브라우저 인쇄)로 보조 출력. 서버 PDF 생성은 하지 않음(Replit에 브라우저 엔진 필요).
- **ZIP·XML 구조 검사는 한글 호환을 보장하지 않습니다.** 실제 데이터가 들어간 HWPX를 한글에서 다시 열어 확인해야 합니다.

## 9. 브라우저 확인 시나리오
1. 관리자: 교직원 관리 > 업무 담당자에서 교사 A에게 안전업무 담당, 교사 B에게 앱 운영담당 지정(비밀번호 재확인). 본인 줄에는 지정 단추가 없음.
2. 교사 A(안전): 메뉴에 상황판·훈련일지. 지진 모의훈련 발령 → 담임이 학급 보고 → 교감(또는 관리자)이 종료.
3. 교사 A: 훈련일지 > '훈련일지 만들기' → 시스템 기록(미보고 학급 표시) 확인 → 교직원 인원·소요 시간·O/X·반영사항 입력 → 저장하기(판 2) → 미리보기(본문+붙임) → 한글(HWPX) 내려받기 → 한글에서 열기·편집·인쇄.
4. 교사 B(운영): 교직원 승인·학급 배정 가능, 상황판·발령 메뉴 없음.
5. 교감: 훈련일지 열람·내려받기 가능, 수정 단추 없음, 교직원 메뉴 없음.
6. 관리자: 교사 A의 안전업무 해제 → 교사 A가 발령 시 '권한 없음'.
