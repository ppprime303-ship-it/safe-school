# STEP 3-D 기존 시스템 영향 분석(2차 개발 예상 범위)

기준: `step-3c-ui` `8257b62`의 실제 코드·스키마. **이번 1차 작업에서는 아래 어느 것도 바꾸지 않았습니다.**

## 1. 필요한 화면(client)
| 화면 | 위치 | 내용 |
| --- | --- | --- |
| 훈련일지 목록 | `/s/:schoolId/reports`(관리자 메뉴 1개 추가) | 종료된 이벤트별 일지 상태(없음/작성 중/작성 완료) |
| 일지 편집 | `/s/:schoolId/reports/:id` | 시제품 구성 + 저장하기·작성 상태(3-C와 같은 방식), 수정 이력 |
| 상황판 종료 후 | 기존 `BoardPage` | '훈련일지 만들기' 단추 1개 추가(기존 동작 변경 없음) |

## 2. 필요한 서버 API(`/api/schools/:schoolId/…`, 관리자 전용 예정)
| 메서드·경로 | 내용 |
| --- | --- |
| GET `drill-logs` | 목록 |
| POST `events/:eventId/drill-log` | 초안 생성(이벤트당 1건, 다시 요청하면 기존 것 반환) — 종료된 이벤트만 |
| GET `drill-logs/:id` | 일지 + 시스템 기록 참고값(학급별 보고·미보고·수정 이력) |
| PATCH `drill-logs/:id` | 저장(판 번호 조건부 갱신, 409) |
| GET `drill-logs/:id/export?format=pdf\|hwpx` | 내려받기(형식은 검증 후 단계적으로) |
- 학교 격리: 기존과 같이 모든 조회를 `schoolId`와 함께, 다른 학교 ID는 404.

## 3. DB 변경 필요 여부
- **필요함(추가형 새 마이그레이션 1개 예상, 기존 테이블 변경 없음)**:
  - `drill_logs`: 학교·이벤트(UNIQUE), 서식 종류·버전, 작성 상태, 판 번호, 교직원 입력값(JSON: 참가 인원·역할·평가·비고·반영사항), 자동값 스냅숏(생성 시점 기록), 작성·수정자·시각
  - `drill_log_revisions`: 판별 이력(3-C와 같이 DB 트리거 자동 기록)
  - (선택) 학교별 서식 기본값(역할 구분·평가 항목) — 처음에는 JSON 열 하나로 충분
- 사진 저장은 별도 결정 전까지 만들지 않음.
- 실제 마이그레이션 SQL은 승인 후 3-C와 같은 절차(초안 → 임시 DB 점검 → 사용자 검토 → 별도 승인 후 Replit 적용)로 진행.

## 5. 기존 기능에 영향을 줄 가능성
- 낮음: 새 테이블·새 라우트·새 화면 추가 방식. 상황판에는 단추 1개만 추가.
