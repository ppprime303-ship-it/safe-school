# 학교 데이터 출처와 연동 정책

## 출처 구분

모든 학교·학급 데이터에 출처를 기록합니다(`DataSource`).

| 값 | 의미 | 현재 사용 |
| --- | --- | --- |
| `schoolinfo` | 학교알리미 공시 OpenAPI | 학교 검색, 학교 기본정보, 학년별 학급수·학생수(참고) |
| `neis` | **나이스 교육정보 개방 포털**(공개 데이터, open.neis.go.kr) | STEP A: 학교기본정보 조회 어댑터만 준비(실제 호출 전, 저장·연결 없음). 나이스 **업무 시스템**(학교 내부 행정정보)은 사용하지 않음 — 아래 '나이스: 개방 포털과 업무 시스템' |
| `manual` | 학교 관리자 직접 입력·확인 | 학급별 재적, 담당 배정 |

## 학교알리미에서 실제로 가져오는 것

| 항목 | API | 확인 상태 |
| --- | --- | --- |
| 학교명·학교코드·학교급·교육청·주소·폐교 여부 | 학교기본정보 `apiType=0` | 요청 인자·출력 필드를 공식 페이지·출력값 파일과 대조함(2026-10-27). **실제 응답은 인증키 발급 후 확인 필요** |
| 학년별 학급수·학생수(합계) | 학년별·학급별 학생수 `apiType=09` | 공식 출력값 파일로 확인(2026-10-27): 초·중·고 모두 n학년 = `COL_Cn`·`COL_Sn`. 그전 코드는 중·고를 다른 열로 잘못 읽었음(기본 꺼짐이라 사용된 적 없음, 수정함). 실제 응답 확인 전까지 `SCHOOLINFO_GRADE_DATA` 꺼짐 유지 |
| 학급별 학생 수 | 제공되지 않음(학년 합계만) | 학급별로 나누지 않음. 관리자가 확인 |
| 공시 기준일 | 응답 필드 미확인 | 있으면 저장, 없으면 비움. 공시연도와 조회 시각은 항상 저장 |

공식 API에는 학교명 검색 인자가 없어 학교급·시도(또는 시군구) 단위 목록을 받아 `school_directory_entries`에 저장한 뒤 이름으로 검색합니다.

### 시도·시군구 코드(2026-10-27 공식 코드표)
- 공식 '시도시군구코드.xlsx'에서 `shared/schoolinfoRegions.ts`를 만들었습니다(시도 16, 시군구 256). **2026-07-01 전남광주통합특별시(12) 신설, 광주(29)·전남(46) 삭제.**
- 요청인자 `sggCode`(5자리)는 공식 페이지에 **'선택'**으로 적혀 있습니다. '2026-01-01 이후 신규 인증키는 시군구 필수'라는 정책은 공식 페이지에서 확인하지 못했습니다. 두 경우 모두 동작하도록:
  - 화면에서 시군구를 고르면 그 시군구 단위로 받고 최신 여부도 그 단위로 판단합니다(`sgg_code` 열).
  - 발급받은 키가 시군구를 요구하면 `SCHOOLINFO_SGG_REQUIRED=true` → 시군구 없는 요청은 API를 부르지 않고 저장된 목록으로만 검색합니다.
- 예전 코드(29·46)로 저장된 **검색 목록** 행은 지우지 않고, 시도 12로 검색하면 함께 보여 줍니다(읽기만, 최신 여부 판단에서는 제외). 같은 학교를 새 코드로 다시 받으면 그 목록 행은 학교 코드 기준으로 공식 응답 값으로 갱신됩니다(STEP A 이전과 같은 목록 갱신 방식). **등록된 학교 정보(`schools`)는 목록 갱신으로 바뀌지 않습니다.**
- 코드표 파일에는 기준일이 적혀 있지 않습니다. 통합 근거는 공식 페이지의 시도 목록·교육청 바로가기('광주광역시교육청 비노출 26.06.30')입니다. 예전 코드로 요청했을 때 실제 API가 어떻게 응답하는지는 실제 호출로 확인합니다.

## 덮어쓰기 금지 원칙

- 공시자료는 `school_public_data_snapshots`에 **스냅숏으로만** 저장합니다(출처 주소, 공시연도, 기준일, 원본, 조회 시각).
- 실제 운영 데이터(`classes`의 재적, 담당 배정, 재난 보고)는 공시자료가 바뀌어도 자동으로 바뀌지 않습니다.
- 학급 구조 적용은 관리자가 직접 실행하며, **없는 학급만 추가**합니다. 기존 학급은 수정·삭제하지 않습니다.
- 재난 보고는 발령 시점 재적 스냅숏(`enrolled_snapshot`)을 쓰므로 이후 변경과 무관하게 보존됩니다.

## 나이스: 개방 포털과 업무 시스템
| 구분 | 나이스 교육정보 개방 포털(open.neis.go.kr) | 나이스 업무 시스템(학교 행정) |
| --- | --- | --- |
| 데이터 | 누구나 조회하는 **공개** 교육정보(학교기본정보, 학사일정 등) | 학생 학적·성적·출결, 교직원 인사 등 **학교 내부 행정정보** |
| 인증 | 포털 인증키(소셜 로그인 후 즉시 발급) | 기관 인증서·내부망, 학교·교육청 권한 |
| SAFE SCHOOL | STEP A: 학교기본정보 조회 어댑터(서버 전용, `server/src/integrations/neis.ts`). 실제 호출·저장·연결 전 | **접근하지 않음.** 아래 계획은 공식 승인이 있을 때만 다시 검토 |
- 개방 포털 자료로도 학교알리미 목록이나 운영 DB의 학교 정보를 **덮어쓰지 않습니다.** 두 기관의 학교 코드 대응은 `matchNeisCandidates`가 이름·주소·교육청으로 '후보'만 내고, 연결(`school_external_ids`, source='neis`)은 관리자가 확인한 뒤에만 합니다(연결 화면은 아직 없음).
- 학생·교직원 개인정보를 나이스 개방 포털로 보내지 않습니다(요청 인자는 학교명·교육청 코드·학교 코드뿐).

## 나이스 업무 시스템 연동(학교 내부 행정정보 — 공식 승인 전 금지, 현재 계획 없음)

1. **식별코드 매핑**: 기존 학교에 `school_external_ids (source='neis', external_code=나이스 표준학교코드)`를 **추가**합니다. 학교·학급·교직원·재난 기록은 삭제하거나 다시 만들지 않습니다.
2. **매핑 확인**: 학교알리미 코드와 나이스 코드의 대응은 이름·주소·교육청을 비교한 뒤 관리자가 확인합니다. 한 출처의 코드는 한 학교에만 연결됩니다(UNIQUE).
3. **갱신 방식**: 나이스 재적은 먼저 스냅숏(`source='neis'`)으로 저장하고, 현재 값과 다른 학급을 목록으로 보여 줍니다.
4. **충돌 처리**:
   - 관리자가 확인한 값(`enrolled_confirmed_at` 있음)과 나이스 값이 다르면 자동 반영하지 않고 '차이 있음'으로 표시합니다. 관리자가 선택하면 반영하고 `enrolled_source='neis'`로 기록합니다.
   - 확인되지 않은 학급은 관리자 일괄 승인으로 반영합니다.
   - 진행 중인 재난 상황이 있으면 재적 갱신을 보류합니다.
   - 학년도가 바뀌면 새 학년도 학급을 만들고, 지난 학년도 학급과 기록은 그대로 둡니다.
5. 모든 반영은 감사 로그에 이전 값·새 값과 함께 남깁니다.

## 관리자 자격 확인

첫 신청자에게 관리자 권한을 자동으로 주지 않습니다. 학교와 신청자 소속은 `pending_verification`으로 남고, SAFE SCHOOL 운영자가 자격을 확인한 뒤 `npm run operator -- approve`로 승인합니다. 확인 방법(공문, 학교 대표전화 확인 등)은 학교·교육청과 정해야 하며, 정해지기 전에는 승인하지 않습니다.
