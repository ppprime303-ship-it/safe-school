# 2026-11-02 Beta 배포 준비 1차

운영 VPS·운영 DB·`main`·`integration/production-preservation`·미리보기 DB는 변경하지 않음. Phase 5·6 착수하지 않음.

## T1 기준선
- `safeschool_test`만 사용(주소 확인 후 실행). typecheck·build 통과, 49개 파일 1163건 통과. 미리보기 DB는 스키마 `public`, 마이그레이션 12개 그대로.

## T3 Beta 환경 분리
- 프로필 `beta`, 역할 `beta`: 스키마 `safeschool_beta`, DB `safeschool_beta`, 계정 `ss_beta`, 포트 5100, 사진 `/var/lib/safe-school-beta/` 아래만 허용. 어긋나면 시작 거부.
- `deploy-start`: Beta는 연결 후 실제 DB·계정·운영 스키마 존재 여부 재확인.
- `BETA_DATA_MODE`: `virtual_test`(실제 메일 금지) / `school_pilot`(승인 표시 필요). 표시값은 승인 사실을 검증하지 못함.
- 설정 예시: `deploy/env/beta.env.example`, `deploy/systemd/safe-school-beta.service`, `deploy/sql/beta-roles.sql`, `deploy/postgres/pg_hba.beta.example`. 기존 Prototype 설정 파일은 바꾸지 않음.

## T4 사진 업로드
- 감사 결과: 기존 systemd 읽기 전용 경로·기본 저장 경로·Caddy 1MB가 앱 정책과 충돌.
- 사진 본문은 세션·요청 제한·동시 처리 수·학교 소속 확인 뒤에 읽음(이전에는 인증 전 7MB까지 파싱).
- Caddy 예시 `deploy/caddy/beta.caddy.example`: 사진 POST만 7MiB, 그 밖 1MB.
- `deploy/scripts/beta-backup.sh`: DB 덤프 + 사진 묶음. 가짜 도구로 흐름·거부만 시험, 실제 DB 미실행.
- 첫 시험에서 동시 처리 상한 4는 10건 동시 요청에 503 발생 → 메모리 추정(건당 약 20MB)에 맞춰 8로 조정. 실측 필요.

## T5 동시 보고
- 학급 보고·소재·제보·사진·발령·일지·안내문 제한을 IP에서 로그인 사용자 기준으로 변경. 로그인 제한과 학교 검색 제한은 변경하지 않음.
- 429에 `Retry-After`·`retryAfterSec`, 화면에 대기 시간과 비상연락망 병행 안내. 학급 보고는 입력 보관 후 같은 요청 번호로 자동 재전송(자동 재전송 화면 동작은 자동 테스트 없음).
- `tests/beta2-shared-ip-limit.test.ts`: 공인 IP 하나에 교직원 70명, 모의훈련·실제 재난.
