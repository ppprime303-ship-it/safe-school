## 2. Phase 1-1 상황판 열람 권한과 보고 권한 분리
### 설계 선택과 이유
- 권한을 둘로 나눔: `board.view`(요약, 승인된 교직원 누구나) / `board.detail`(상세, 기존 board.view 보유자 = 관리자·교장·교감·안전업무 담당).
  기존 권한 보유자는 그대로 상세를 보므로 PILOT 1 관리자 화면은 바뀌지 않음.
- 요약 응답은 서버(`restrictBoard`)가 만듦. 학급 메모(학생 이름이 적힐 수 있음)·보고자 이름·부상 인원(학생 건강 정보)·대리 담당 지정 정보는 응답에서 제외 — 화면 숨김에 의존하지 않음.
- 열람 권한은 보고 권한을 만들지 않음: 학급 보고 검사(`submitReport`)는 `board.*` 와 무관하게 학급 배정·대리 지정으로만 판단(관리자 일괄 대리 보고 제거는 Phase 1-3).
- 처음 여는 화면은 `board.detail` 기준으로 바꿔, 담임은 지금처럼 학급 보고 화면에서 시작(요약 상황판은 메뉴에서).
- 상황판 화면의 발령 양식·종료 버튼은 해당 권한자에게만 표시(서버는 원래부터 403).
