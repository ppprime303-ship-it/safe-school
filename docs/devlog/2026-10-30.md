## 2. Phase 1-1 상황판 열람 권한과 보고 권한 분리

- 권한을 둘로 나눔: `board.view`(요약, 승인된 교직원 누구나) / `board.detail`(상세, 기존 board.view 보유자 = 관리자·교장·교감·안전업무 담당).
  기존 권한 보유자는 그대로 상세를 보므로 PILOT 1 관리자 화면은 바뀌지 않음.

## 4. Phase 1-2a 교직원 실명 입력과 학교 관리자의 성명 정정(신규 요구)
### 배경
- PILOT 1 가입 화면은 개인정보 보호를 위해 '닉네임'을 받았음. 재난 대응 시 교직원 확인을 위해 실제 성명으로 전환.

### 구조 감사
- 성명은 `users.display_name` 하나. 모든 화면(상황판 보고자, 대리 담당, 업무 담당, 훈련일지, 안내문)이 요청 시점에 계정 ID로 조회해 표시.
- 보고·수정 이력·감사 기록은 사람을 **계정 ID**로 저장 → 성명을 바꿔도 '누가 했는지'는 유지. 단, 화면 표시는 현재 성명.
- 훈련일지 자동 스냅숏(`auto_snapshot`)은 만들 때의 이름을 JSON으로 고정 보관.
- 한 계정이 여러 학교에 소속될 수 있음(`school_memberships` 학교·사용자 UNIQUE) → 전역 성명을 한 학교 관리자가 바꾸면 다른 학교 화면·기록 표시가 바뀜.

### 설계 선택
- `displayName` 재사용, DB 변경 없음. 새 입력에만 성명 규칙(2~30자, 글자·공백·가운뎃점·하이픈·아포스트로피·마침표, 공백 정리). 기존 계정 이름은 다시 검사하지 않음.
- 성명 정정 권한 `members.rename` 신설 — **학교 관리자만**(앱 운영담당은 승인·배정은 하되 성명은 불가).
- 정정 조건: 같은 학교 승인 교직원, **다른 학교 소속이 전혀 없는 계정**만(있으면 409, 플랫폼 운영자에게 요청), 비밀번호 재확인(10분), 화면에서 본 현재 성명 일치(동시 정정 방지), 사유 필수.
- 성명 외 항목은 요청에서 받지도 않음(스키마가 버림). 감사 기록에 전·후 성명·사유·대상 계정 → 잘못 바꾼 성명도 같은 절차로 되돌림.

### 후속 제안(미구현): 학교별 표시 성명
- `school_memberships.display_name`(NULL 허용, 추가 전용 마이그레이션) — 학교 화면에서는 '학교별 성명 ?? 계정 성명'.
- 다중 소속 교직원도 각 학교 관리자가 자기 학교 표시만 정정. 표시 지점 약 20곳을 학교 문맥 조회로 바꿔야 해 별도 작업 필요.
- 공식 보고서(PDF, Phase 4)에는 작성 시점 성명을 함께 고정 저장 권장.

### 테스트
- 순수 함수 17건(성명 규칙, 가입·인증·정정 스키마, 권한) → 로컬 301건 통과.

## 6. Phase 1-3 공식 학급 대피 보고 권한
### 변경 전 → 후
| 대상 | 변경 전 | 변경 후 |
| --- | --- | --- |
| 학교 관리자(`role=admin`) | 모든 학급 보고·수정('관리자 대리 보고'), 내 학급 목록 = 전체 학급 | 담임 학급·지정된 대리 학급만, 목록도 같음(전체 현황은 상황판) |
| 보조(`assist`) 배정 | 배정 학급 보고 가능 | 보고 불가 — 대리 담당 '부담임 후보' 표시에만 사용 |
| 담임(`homeroom` 배정) | 보고 가능 | 그대로 |
| 대리 담당(사건·학급 지정) | 보고 가능 | 그대로(해제·사건 종료 즉시 철회) |
| 교장·교감·안전업무 담당·일반 교직원 | 배정 없으면 불가 | 그대로 불가 |
| 대리 지정 | 자기 자신 지정 가능 | 자기 지정 403 `self_delegation`, 후보 목록에서도 제외 |
| 같은 요청 번호 재전송 | 누구든 같은 번호면 저장된 보고 반환 | 처음 보낸 사람·같은 학교·사건만(아니면 409·404) |

- 판정 함수 `reportResponsibility`(events.ts) 하나로 생성·수정·목록을 같이 판단. 역할·직책은 보고 권한을 만들지 않음.
- 기존 데이터 호환: DB 변경 없음. 과거 '관리자 대리 보고' 이력·보조 배정·대리 지정 기록은 그대로 보존(권한 판정에만 쓰지 않음).

### 담임·대리 모두 부재 시(제안, 미구현)
- 원칙: 공식 학급 보고를 예외로 열지 않음. 먼저 다른 발령 권한자가 대리 담당을 지정(관리자 본인도 다른 권한자가 지정하면 보고 가능).
- 그래도 지정할 사람이 없을 때를 위한 '관리자 확인 기록'(가칭 `class_status_notes`): 학급·사건·확인자·시각·확인 내용, 상황판에 '공식 보고 아님' 표시로 별도 노출, 집계·훈련일지 숫자에는 넣지 않음. Phase 3 현장 상황 공유와 묶어 설계 권장.

### 운영 안내 문구(배포 시 교직원·관리자 공지용 초안)
> 이번 버전부터 학급 대피 보고는 **담임 선생님**과, 재난 상황 중 **대리 담당으로 지정된 선생님**만 할 수 있습니다. 학교 관리자도 담임 학급이 아니면 직접 보고할 수 없습니다.
> 담임 선생님과 연락이 되지 않으면 상황판 아래 '담당 교사 부재 시 대리 보고'에서 대리 담당을 지정하세요. 자기 자신은 지정할 수 없으므로, 관리자가 직접 맡아야 하면 교장·교감·안전업무 담당 등 다른 발령 권한자가 지정합니다.
> '보조' 학급 배정은 대리 담당 후보로만 쓰이며, 그것만으로는 보고할 수 없습니다.
